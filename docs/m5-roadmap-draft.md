## 一、可靠性清债（M5 主线）

2.0 的卖点是长任务，长任务的下钻与续航体验是卖点上最明显的毛刺（对应「已知边界」表前两行）。

**承诺件（立项即做）**

- **a. Run 明细持久化（口径升级：事件流持久化 = 可回放）**：Run 元快照 + append-only 事件流落盘（延续 `data/tasks/` 挂账口径），服务重启后下钻与回放可用；孤儿轮（服务被杀留下的未收尾轮次）从盘上重建为 `interrupted` 终态——不假装还在跑（会占准入槽），也不误报失败。关闭「已知边界」表第一行。
- **b. 任务级 SSE（口径升级：任务状态机 + 事件序号断线续传）**：任务卡状态 / 确认 / 账单改走推送——增量载荷是全量状态（幂等可重放）+ 快照自愈 + Last-Event-ID 续传；20s 轮询降为兜底心跳。确认弹窗即时化：确认挂起即时推 waiting-approval（挂起是派生态，不落 Task 字段的口径不变），断线重放语义保留。关闭「已知边界」表第二行。

**条件件（小步做或撞上才做）**

- **c. 工具结果治理缝**：工具结果进入 **记忆 / 审计 / 模型输入** 三条链路之前统一做规模控制——三条链路只持一份受控数据（截断预览 + 引用），完整数据落盘保留、按需受控回查（先探结构 → 条件读取 → 全量明细只作文件交付不进上下文）。治理参数面按 trigger / keep / clear_at_least / exclude_tools 四维设计（哪些清、留多少、何时清、豁免谁），清理动作进事件流留痕、可归档全量。触发信号＝长任务工具结果顶爆上下文或摘要被频繁触发。
- **d. 压缩/摘要 token 口径核对**：token 估算覆盖非消息开销（system prompt、工具 schema）；摘要触发以 **token 压力** 为准、消息条数只作辅助——防「当前轮被反复压缩 → 信息不够 → 重复调用同批工具」死循环形态。压缩须**可恢复**：保「指针」（文件路径/URL/沙箱位置）丢内容，产出落盘、主线只留摘要；待办滚动重写刷新注意力。触发信号＝长任务出现重复调用循环，或摘要后仍超窗。
- **e. O2 长跑进程劣化（挂账维持）**：同进程内再次复现即立案。排查时按「流式工具调用协议防御」清单对表：截断参数修复、首分片识别、空工具名、悬挂调用恢复、错误结果回写。

## 三、扩展生态（副线）

- **hooks/插件机制**（114 挂账单开案）：预研约束先记——**扩展点顺序即语义**（例：孤儿轮回收必须排在悬挂工具恢复之后，否则人工确认挂起的轮次先被关掉、错误结果补不进去），实现须显式排序且顺序可解释。权限判定也学固定顺序（hooks → deny → ask → 模式 → allow → 回调），不让规则互相打架。
- **技能渐进式加载 + 工具按需注册**：技能不是一次性全量注入，入口技能读到子技能时才动态注册其工具。触发信号＝技能全量注入顶窗口（技能规模上去才立案）。
- **marketplace 上架 / CHANGELOG**：维持 118 原触发信号（外部用户要求一键安装 / 要求离线可读变更史）。

## 五、多任务编排（大迭代主线：从 demo 到 harness 的分水岭）

定位：现在是一个「会干活的 agent」，缺的是「能管活的 harness」。a+b 落地的事件流 + 状态机 + 推送面就是这条线的地基；三步走随触发信号逐段立项，不在 M5 一次吞下。

**三步走（方向，不是排期）**

1. **单 agent 多任务**：任务队列与并发执行（并行隔离默认 worktree，完成后显式合并回工作分支）、编排控制台（任务面板升级：聚合全部在飞任务的状态/耗时/token/等待审批，就地打断且区分「排队打断 / 即时打断」并警示半写风险）。
   *已有件*：任务队列并发上限 + 触发式调度（117 §1）、worktree 工具（create/merge/discard + 确认）；控制台的耗时/token 展示与打断语义区分已落任务面板；**并行隔离调度接线已落**（chat 任务默认进任务沙箱，续跑复用，完成后显式「合并入库/丢弃改动」收口，启动回收认领沙箱不误清）。*缺口*：控制台聚合视图；skill 任务沙箱（锚 repo_root 的隔离，暂不做）。
2. **子 agent 委派**：三条铁律——上下文隔离、只回传摘要、编排者禁读细节文件（防上下文污染）；并行 fan-out + 主线聚合，闲时子 agent 零成本挂起；checkpoint 要**双层**（上下文快照 + 文件快照成对——只回退上下文不回滚文件是已知的坑）。
   *已有件*：spawn_subagent/spawn_step（临时会话隔离、只回传 conclusion、工具子集、轮数预算、worktree 模式）；**fan-out 聚合已落**（fan_out_subagents：一次派 N 件并行执行、程序侧按序确定性聚合结论回主线，递归防护进禁止单）；「只回传摘要」已结构化（结论/改动摘要超长截断 + 指针化——「禁读细节」现为结构上限）。*缺口*：双层 checkpoint、闲时子 agent 零成本挂起、「禁读细节」的读权限级封锁（现只有结构上限，编排者主动去读细节文件仍靠纪律）。
3. **人机协作协议化**：确认卡升级为 interrupt——结构化参数 + 用户**编辑参数后恢复** + 不重跑已完成工作；执行风险分档（低风险直行 / 中风险监控 / 高风险拦截确认）；自动放行必须留 `auto-approved` 痕迹（可审计），回放兜底可观测性。
   *已有件*：确认卡（L2 裁决）+ steer 纠偏信箱。*缺口*：interrupt 结构化参数与「编辑参数后恢复」、风险分档、auto-approved 痕迹。

**预研约束（撞上即用）**

- 工具/技能层接 MCP 一类标准协议（含 registry 治理思路），前端事件词汇对齐通用 agent-UI 事件面（run/interrupt 生命周期），观测接 trace 透传——自研面收缩到「任务编排 + 状态持久化 + 人机协作」三件核心。
- 子 agent 间不建共享记忆总线，靠显式传参 + 共享任务清单（含依赖阻塞）+ 文件认领锁。

**触发信号**

- 外部试用出现「同时想开第二件事」的诉求 → 立项第 1 步。
- 出现「专人跑测试/审 diff」的质量诉求 → 立项第 2 步的对抗式校验位。
- 确认弹窗出现「改参数重发」的抱怨 → 立项第 3 步。
