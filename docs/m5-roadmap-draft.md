## 一、可靠性清债（M5 主线）

2.0 的卖点是长任务，长任务的下钻与续航体验是卖点上最明显的毛刺（对应「已知边界」表前两行）。

**承诺件（立项即做）**

- **a. Run 明细持久化**：Run 明细落盘（延续 `data/tasks/` 挂账口径），服务重启后下钻可用。关闭「已知边界」表第一行。
- **b. 任务级 SSE**：任务卡状态 / 确认 / 账单改走推送，去掉 20s 轮询；确认弹窗即时化（断线重放语义保留）。关闭「已知边界」表第二行。

**条件件（小步做或撞上才做）**

- **c. 工具结果治理缝**：工具结果进入 **记忆 / 审计 / 模型输入** 三条链路之前统一做规模控制——三条链路只持一份受控数据（截断预览 + 引用），完整数据落盘保留、按需受控回查（先探结构 → 条件读取 → 全量明细只作文件交付不进上下文）。触发信号＝长任务工具结果顶爆上下文或摘要被频繁触发。
- **d. 压缩/摘要 token 口径核对**：token 估算覆盖非消息开销（system prompt、工具 schema）；摘要触发以 **token 压力** 为准、消息条数只作辅助——防「当前轮被反复压缩 → 信息不够 → 重复调用同批工具」死循环形态。触发信号＝长任务出现重复调用循环，或摘要后仍超窗。
- **e. O2 长跑进程劣化（挂账维持）**：同进程内再次复现即立案。排查时按「流式工具调用协议防御」清单对表：截断参数修复、首分片识别、空工具名、悬挂调用恢复、错误结果回写。

## 二、体验与生成质量（副线）

- **长任务异常形态清单**补进保险丝与异常面板文案：重复调用循环、悬挂调用、孤儿轮（未收尾的中断轮）、部分子步失败。异常可见是既有口径（ADR 093），这里只补形态词汇。
- **Brief 生成质量**：首例「生成质量缺陷」触发信号维持，复现即立案。
- **第三处确认面**：触发信号维持（聊天页 + 任务面板两份确认 UI 是双栈现状的既有债；出现第三处确认 UI 时统一真值源）。

## 三、扩展生态（副线）

- **hooks/插件机制**（114 挂账单开案）：预研约束先记——**扩展点顺序即语义**（例：孤儿轮回收必须排在悬挂工具恢复之后，否则人工确认挂起的轮次先被关掉、错误结果补不进去），实现须显式排序且顺序可解释。
- **技能渐进式加载 + 工具按需注册**：技能不是一次性全量注入，入口技能读到子技能时才动态注册其工具。触发信号＝技能全量注入顶窗口（技能规模上去才立案）。
- **marketplace 上架 / CHANGELOG**：维持 118 原触发信号（外部用户要求一键安装 / 要求离线可读变更史）。
