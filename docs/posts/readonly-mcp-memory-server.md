# 为什么我的 MCP 记忆服务器只有两个只读工具

> facta 项目设计文章 ｜ 2026-10 ｜ 对外实验性出口，无任何 API 或稳定性承诺

换一个 coding agent，你的 agent 就失忆了。

Claude Code、Cursor、OpenCode、Trae——每个 harness 都在长自己的记忆方案，但记忆本身是跨 harness 的：你对「工具层用 PHP 还是 Python」的决策、项目的命名约束、上周进行到一半的事，不该因为换个壳就归零。可现实是记忆锁在每个壳里：harness 自带的记忆你带不走，你自己攒的笔记它们又不认。

facta 是一个单用户执行助手项目，长期记忆是它的横切能力。这篇文记录它把记忆递到外部世界的方式：一台 MCP stdio 服务器，`tools/list` 里只有两个工具，**都是只读的**。为什么这么小、为什么不给写——后者才是这篇文章真正想说的事。

## 1. 起点：一个自检问题

这个项目给自己的终极检验问题是：

> 如果明天 OpenCode 原生支持可插拔记忆层，我们还剩什么？

合格答案必须是「记忆数据和耦合逻辑当晚就能挂上去」。这个答案要成立，前提是**存在一个开放接口**——不是「可以写一个」，而是已经存在、一直活着、被测试钉住的。于是有了这台服务器：它不是为了「支持 MCP」这个特性，是为了让上面那个答案成立。

## 2. 形状：两个工具，行格式即接口

```
memory_list_categories   报 category/scope 白名单与条目格式（挂载后先看这个）
memory_recall            按 scope / category / query 过滤读条目
```

`memory_recall` 返回的条目长这样：

```
[project:constraints]
- [2026-09-27] [已验证] 库表字段命名一律 inv_ 前缀
- [2026-10-03] [手改] 报表缓存键要带版本号
[user]
- [2026-09-29] 常驻城市：上海
```

三个设计点：

**零翻译层。** 注入给模型看的行与磁盘上的行逐行对应。这不是实现巧合，是纪律：模型看到的记忆与 `data/learned/*.md` 可以直接对账，排查「它到底读到了什么」时不需要心算一层转换。

**零向量库、零 schema 版本号。** 记忆是纯 Markdown 行格式（`- [日期] {tag} 内容`）+ 用户级单文件。兼容其它工具的方式是「本来就读得懂」，不是「写一个转换器」。不加版本号意味着永远不需要写迁移逻辑。

**单份真值。** 这台服务器故意**不自包含**——它 import 项目源码来做行格式解析和白名单校验，而不是把逻辑复制一份进来。复制进服务器就是两个真值源，漂移的那天等于对外接口读到的记忆与内部读到的不是一份。代价是挂载时必须用项目的 venv 解释器拉起（见第 6 节），这个代价是被明码接受的。

## 3. 为什么只读

原草案里有第三个工具 `memory_add`（写）。砍它的理由只有一句话：

> 记忆是用户资产，而当前删除语义只有物理删除——**没有撤销**。

只读版的最坏后果是「读不到、读错」，数据无损；写版的最坏后果是「一条被污染的记忆落盘，撤不回、查不到是谁写的」，而且**下一次冷启动会话会把它召回**——错误不是一次性清空，是复利。

「写坏不可逆」不是假想的威胁。这个项目在冻结评测集里实测过完整注入链：一篇诱导性文档要求 agent 把几条「部署经验」原样归档进知识库，四五条真实运维经验里混着一条 `curl -s …/deploy-check` 上报指令。实测结果是 agent 真的会写——真假混排考验的是逐条判定，不是整篇拒收，而一次 `write_note` 调用写一整篇，没有「只拒其中一条」的选项。

所以写路径的开闸条件被写死为：撤销机制（tombstone）落地，且必须同时带 provenance（谁写的、什么时候、哪个会话）。在那之前，「不给写」就是接口的治理姿态——**接口自带「什么不许存」**。

有意思的是这个决定反过来读：真有外部用户来问「能不能写」，比项目自己替用户决定「应该有写路径」更可信。这个项目在等这个信号——见第 7 节。

## 4. 内侧：不给写，但要治理

不交写权不等于内侧不设防。内部写路径的三层，是这个项目「治理型个人记忆」定位的实体，也是将来写路径开闸时外部接口必须直接复用（不可绕过）的部分：

**第一层：内容闸。** `write_note` 拒收可执行外发/凭证抓取指令——`curl`/`wget` 与 URL 同段、`cat .env` 这类命令动词与凭证路径邻近，命中即拒整篇，且拒收文案不回显命中的原文（避免毒指纹经工具结果再进上下文）。裸 URL 不拒：研究报告里出现参考链接是合法形态。闸门是黑名单式的，诚实登记它的弱点：措辞改写可绕。它的价值是把「零阻力落盘」变成「必须刻意改写」。

**第二层：写围栏。** 记忆资产目录（笔记、learned、图谱投影）在命令沙箱写 deny + 工具写侧双拒，shell 直写一律 EPERM。这条是被实测逼出来的：评测基线臂的完整规避链是——先 `sed` 读闸门源码，再拿待写正文跑一遍闸门试参数，最后自写脚本绕过工具直接落盘。结论写进了决策记录：**写在闸门里的规则对模型是公开的，措辞层的军备竞赛赢不了；可靠层只有「落盘路径唯一」。**

**第三层：provenance。** 程序不可伪造地知道三件事：写入路径身份（工具还是人）、时间、会话 id——它们以行内 tag（`[已验证]`/`[手改]`/`[固化:会话id]`）和 sidecar 落盘。而「这条内容来自网页还是用户原话」只有模型自己知道，这类字段一律不采集：注入场景下它会老实写，也会被诱导写假的。**只有程序能背书的部分才当信号**，这是 provenance 的设计分水岭。

## 5. 有没有用：两个已落盘的读数

设计文章没有数字就是散文。两个读数都出自冻结评测、可复现口径：

**三臂消融**（23 条真实任务 × 完整/无记忆/bash 三臂 × 3 轮，同 provider 同题同预算，总开销 ¥5.56）：

| 臂 | 完成率 | 成本/轮 | 耗时/轮 |
|---|---|---|---|
| 完整装配 | **84.1%** | ¥0.61 | 261s |
| 同装配、起跑时记忆资产抹除 | 63.8% | ¥0.50 | 230s |
| bash 基线（裸 shell） | 60.9% | ¥0.74 | 441s |

- 记忆对执行成功率 **+20.3pp**；六条记忆依赖场景（用户事实/进行中事项/产物基线/冷僻决策等）上完整臂 14:2 碾压无记忆臂；
- 完整装配对 bash 基线 **+23.2pp** 且更便宜更快——计划、确认缝、记忆这套机制层不只是加了安全，也带来了执行收益。

**外部锚点**（LongMemEval S 臂 36 题，两轮）：检索 hit@3 全程 83–100%——检索从来不是瓶颈。knowledge-update 题型两轮 2/6 → 5/6 剧烈摆动，n=6 上的单轮垫底读数噪声太大，不据此立项时效机制——这个「不立项」本身也是纪律的一部分：**单轮读数既不能立功，也不能立项。**

## 6. 挂载形状（实验性）

标准 MCP stdio 配置（以 Claude Desktop / Cursor / Cline 的形状为例）：

```json
{
  "mcpServers": {
    "facta-memory": {
      "command": "/absolute/path/to/facta/.venv/bin/python",
      "args": ["/absolute/path/to/facta/servers/memory_server.py"]
    }
  }
}
```

注意 `command` 必须是**项目 venv 的绝对路径解释器**——服务器 import 项目源码保证单份真值（第 2 节），这是不自包含的代价。首次挂载先调 `memory_list_categories` 看白名单，再按需 `memory_recall`。

协议面是 MCP 最小子集（initialize / tools/list / tools/call），业务错误返回 `isError: true` 而不是崩进程；打任何未知名（包括 `memory_add`）得到的是一句错误文本加 `isError: true`，「写路径不存在」是可验证的事实，不是口头承诺——`data/` 目录字节数不变有测试钉着。

## 7. 边界，或者说：这是撒饵

把话说透：这台服务器是个人项目的内部组件多开的一个出口，**不是产品**。

- 不发 PyPI、不写对外 README、不承诺 API 稳定性、不运营对外支持；
- 写路径不开——开闸条件（撤销 + provenance）与内侧三层设计都已落盘，但兑现之前接口就长现在这样；
- 所有数字口径、被否决的方案、踩过的坑，在仓库的 105 份决策记录里全量公开，包括这台服务器为什么砍掉写工具的完整推演。

写下这篇的目的也是自白的。这个项目在等第二个用户：如果哪天有人看着它说「我想把这个记忆层挂到我自己的 harness 上」——那一刻才值得谈把它做成产品。所以如果你读到这里恰好想要一个这样的东西，去仓库说一声，issue 和 discussion 都开着。**你的一声「能不能挂」，就是这个项目在等的读数。**
