# 产品定位（一页纸）

> 活文档（2026-09-16 首版）：与 roadmap 同生命周期，随真实使用迭代。定位决定的是「围着什么转」（优先级/体验/打磨方向），不是能力上限。

## 一句话定位

**通用个人 agent**：服务一个人的完整工作与生活——知识、日常、工程三块并列为核心场景，能力通用、锚点在「个人」（单用户）。

定位与能力分离（业界实证：coding agent 商业产品问什么都能答）：Cursor 围着代码转是打磨方向的选择；我们围着「一个真实用户」转，哪个场景使用频率高/痛得深，哪个优先——**优先级由真实使用数据动态排序**，不预先垂类化。

## 核心场景（三列并列，不分主次）

| 场景 | 内容 | 一句话验收（好用标准） | 现状 |
|------|------|----------------------|------|
| 知识伴侣 | 学习问答、规划讨论、概念验证 | 基于我的笔记回答；答不了诚实说；偏好与决定跨会话记住 | ✅ 已建成（RAG+记忆+固化） |
| 个人助理 | 实时信息、日常询问、待办 | 天气/时间/实时信息一句话可得；说过的事不重复问 | 联网工具进行中；待办已排期 |
| 工程协作 | 项目读写、改动交付 | 能读改项目文件并展示 diff；每次改动可审计 | S4 工具三件套 |

场景优先级 = 近期真实使用频率与痛点深度（例：联网需求两次实测失败 → 排到最前）。

## 功能语义表（防漂移）

- **任务** = 个人待办：UI 创建/勾销，agent 可读写。工程委派（长任务 Run）是 S4/S6 的能力，不占「任务」一词。
- **联网** = web search + fetch 两个内置工具：补实时信息缺口，不是要做搜索引擎。
- **规则文件** = AGENTS.md（S5）：改行为不碰代码。

## 显式不做（同否决档案纪律）

- 多用户/服务他人（通用 ≠ 公共；S8 多入口仍是单用户多渠道）
- 通用搜索引擎替代（联网是场景补充）
- IDE 形态（远期触发信号见否决档案）
