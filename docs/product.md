# 产品定位（一页纸）

> 活文档：与 roadmap 同生命周期，随真实使用迭代。定位决定的是「围着什么转」（优先级/体验/打磨方向），不是能力上限。
> v2（2026-09-18）：外部评审挑战「三场景并列=没定位」后定稿——场景押执行、能力押记忆、通用性来自用户身份开放（[021](decisions/021-direction-decisions.md)）。v1（2026-09-16）：通用个人 agent、三场景并列（[014](decisions/014-product-positioning.md)）。

## 一句话定位

**个人执行助手**：能写代码、能扛复杂任务的个人 agent。

主轴是**执行**（把事办成，不是陪聊）；护城河是**极强的个人记忆**（越用越懂你）；外延是**通用能力**——通用性来自用户身份的开放：单一用户的真实生活本就横跨工程/知识/日常，场景因真实使用自然生长，**是溢出效应而非设计目标，不预设、不摊平**（此因果句写死，防退化回「三场景并列」）。

## 定位三要素

- **执行主轴**：产品形态首先是「个人执行助手」，验收标准是任务被办成——代码改完且测试过、调研完成且落笔记、行程可执行。对评审「押知识伴侣」主张的回应：记忆是护城河（能力），不是场景——取其前提（记忆最值钱），弃其结论（押问答场景）。
- **记忆护城河**：记忆是横切能力，服务所有场景——跨会话记住偏好/决策/教训（data/learned 固化管线），检索带出处（RAG 溯源）。**护城河必须被感知才有产品价值**：记忆面板（查看/编辑 agent 记住了什么）列为高优前端需求（「护城河可视化」）。
- **通用外延**：场景清单是溢出结果的记录，不是设计目标。新场景的进入方式=真实使用自然生长（现有四例：模块重构、调研落笔、行程规划、待办追踪），不是路线图预设。

## 场景清单（溢出记录，随使用生长）

| 场景 | 内容 | 一句话验收（好用标准） | 现状 |
|------|------|----------------------|------|
| 工程执行（主轴） | 项目读写、改动交付、复杂多步任务 | 能读改项目文件并展示 diff、跑测试、扛多步任务交付 | S4 工具三件套 ✅；规划能力=定位与现状的最大差距（S5 重定义主攻） |
| 知识伴侣 | 学习问答、规划讨论、概念验证 | 基于我的笔记回答且带出处；答不了诚实说 | ✅ RAG+溯源；固化管线 ✅ |
| 个人助理 | 实时信息、日常询问、待办 | 实时信息一句话可得；说过的事不重复问 | 联网 ✅；待办 ✅ |

场景优先级 = 近期真实使用频率与痛点深度（证据见台账）；工程执行为默认主轴，其余按数据生长。

## 功能语义表（防漂移）

- **任务** = 个人待办：UI 创建/勾销，agent 可读写。工程委派（长任务 Run）是 S4/S6 的能力，不占「任务」一词。
- **联网** = web search + fetch 两个内置工具：补实时信息缺口，不是要做搜索引擎。
- **Agent 对象**（S5）= 带独立 system prompt/工具子集/预算/记忆的执行单元（吸收原「规则文件 AGENTS.md」与 SYSTEM_PROMPT 外置——二者本就是 Agent 对象的属性）。
- **编排** = agent.md 声明式文本定义（git 可 diff、agent 可读写）+ mermaid 可视化阅读；拖拽编辑否决（见 veto-archive）。

## 显式不做（同否决档案纪律）

- 多用户/服务他人（通用 ≠ 公共；S8 多入口仍是单用户多渠道）
- 通用搜索引擎替代（联网是场景补充）
- IDE 形态（远期触发信号见否决档案）
- 拖拽式编排编辑（见 veto-archive；触发信号=出现不用画布就维护不了的多 agent 流程）

## 使用数据台账（定位的证据来源，随归档更新）

- 2026-09-15（五段）：架构/重构讨论 ×3、规划 Agent ×1、实时信息（天气/股市）×2 失败 → 联网排最前
