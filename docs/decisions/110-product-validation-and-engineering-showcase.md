## 背景

本轮分析后，用户明确三个目标的排序为 **1 = 3 > 2**：

1. 吸引外部用户，验证产品价值。
2. 成为自己每天会用的助手。
3. 工程学习与求职作品展示。

据此，长期自用不再是产品验证的首要目标。自用承担首轮检查和问题发现，
外部需求验证与可深入讲解的工程作品共同决定下一阶段投入。两项目标各自
验收：工程完成度不能替代外部需求证据，少量试用也不能替代工程质量。

098 已选定开发方案评审作为首个切口，但原型与五例验收仍未完成。现有执行、
记忆、检索和恢复能力可供复用；下一阶段优先把这些能力组织成一次可体验、
可核对结果的工作流，再由实际阻塞决定新增工程项。

## 裁定

### 1. 同一个原型服务两项目标

首批目标用户仍是自己负责项目方向、经常委派 AI 开发、需要亲自判断方案的
个人开发者。产品承诺沿用并明确为：

> 在让 AI 开工前，结合仓库实际和已确认的项目决定检查开发方案，指出有依据的
> 遗漏、偏离和不必要的工作，帮助用户决定是否开工及最小修正范围。

面向使用者，展示任务、输入、评审结果及使用成本；面向开发者和招聘者，解释
支撑该结果的设计取舍、实现、验证和失败边界。两种表达复用同一原型与真实案例，
不并行建设一套展示用系统。

“从零自研、无框架”保留为工程实现说明；产品价值需要通过实际任务单独证明。

### 2. 保留 D01 优先，D02 先作为减少准备成本的能力

- **098/D01 开发方案评审与范围控制**：下一阶段产品主线。
- **098/D02 Brief 与历史决定复用**：先在 D01 中按需复用相关背景；若整理材料
  成为主要阻塞，再提前验证 Brief 生成，不先建设第二套独立产品。
- **098/D03 源码联动讲解**：继续后置，出现更强的真实需求证据时再重排。

通用个人助手继续自用和维护；新增通用功能、IDE 深度集成与独立记忆产品，
按其既有裁定和真实需求另行判断，不作为本轮外部试用的前置。
本案不推翻 architecture 的能力建设原则，调整的是本阶段交付顺序。

### 3. 验证顺序改为少量自测后尽早外部试用

| 阶段 | 首轮目标 | 产出与后续判断 |
|------|----------|----------------|
| V01 最小原型 | 能在用户指定仓库上完成开工前评审 | 输入目标、验收要求与方案，输出带证据的短评审；支持无问题与材料不足 |
| V02 自用检查 | 用 1–2 个真实自有任务排除明显阻塞 | 记录读仓库、准备材料、意见核实等摩擦；能完成流程后即可进入外部试用 |
| V03 外部探索 | 邀请 3–5 位目标开发者，使用其真实任务和可用于试用的项目 | 记录实际完成、采纳、拒绝、流失及再次使用行为；反馈与自用记录分开 |
| V04 公开案例与去留判断 | 整理一个可公开复核的案例，并决定下一轮投入 | 保留原方案、依据、用户取舍、执行结果及局限；结论可以是继续、转向或暂停 |

人数与任务数是首轮探索规模，不是需求已成立的判定阈值。招募不足时记录到达和
退出情况，区分渠道、价值表达、接入成本与需求问题；不以持续加功能代替判断。
V04 的案例可以来自自用或经同意公开的外部任务，来源必须标明。自用五例仍可
继续积累，但不再作为 V03 的准入条件，也不替代外部反馈。

### 4. 首版只补齐评审所需的接入与证据链

沿用 098 的输入输出和只读评审边界。每条影响交付的意见给出需求、代码或有效
决定的依据、具体影响和最小修正；区分事实、推测与待验证项，不设问题数量配额。
允许用户采纳、驳回或暂缓；评审意见不自动升级为项目决定。

本轮读码基线为 `8b31672`。`orchestrator/assemble.py` 默认把主 Agent 的
`workspace_root` 绑定到 `paths.WORKSPACE_ROOT`（Facta 仓库）；107 的桥只投递
路径与选区，尚不能据此声称已具备完整的外部仓库读取能力。因此，V01 需解决
用户明确指定被评审仓库的接入，并验证确实读取了该仓库。

具体参数、界面和模块划分留给实现方案；读文件范围限制在所选项目，项目记忆
归属明确，避免把不同项目的决定混作当前约束。不通过放宽全局文件权限解决接入。
复用现有入口；新建 IDE、自动改代码、自动执行方案中的命令、执行期监控与自动
叫停不属于首版。Qoder 工作材料不纳入本轮验证，沿用 098 的范围约定。

### 5. 分别记录产品收益、记忆增益和工程质量

| 维度 | 至少记录 | 不能据此推断 |
|------|----------|--------------|
| 产品收益 | 准备、等待、阅读和核实时间；有证据且被采纳的意见；误报成本；实际方案变化；再次使用行为与理由 | 问题条数、礼貌认可或单次体验不等于持续需求与付费意愿 |
| 记忆增益 | 能做对照时比较普通评审与加入相关有效历史后的结果，尽量固定模型、任务和其余输入 | 内部消融不能直接折算为用户节省时间或返工减少比例 |
| 工程质量 | 关键设计取舍、适当的检查、可复现结果、失败案例及处理边界 | 架构层数、ADR 数量或测试数量不等于产品价值 |

对照中的差异与限制必须记录；无法对照时标为观察，不把模型差异或已知任务结果
造成的优势归因于记忆。历史任务回放与新任务分开。096 的 84.1% 与 63.8% 仅为
内部任务集的完成率读数；其中确认次数是自动批准事件，不能当作真人投入时间。

### 6. 案例与 README 围绕实际结果组织

公开案例至少保留：任务目标与原始方案、仓库版本、必要输入、评审输出及依据、
用户取舍、实际执行结果或未执行说明、使用成本、失败与局限。可复现部分附运行
方式；不能公开或复现的部分明确说明，不用合成结果填补证据缺口。

后续 README 优先让访问者看到具体使用场景、真实案例和体验入口，再展开架构
与实现取舍。案例尚未产生时可展示明确标注的演示，不能写成真实用户成果。
本 ADR 只规定后续调整方向，本次不改写 README 的产品介绍或宣布原型已发布。

工程学习围绕已发现的问题展开，例如外部项目的读取范围、项目记忆归属、意见
的证据追溯及记忆对照验证；不为作品展示另造一套与使用过程无关的基础设施。

## 去留条件与备选方向

- **继续 D01**：出现有依据且改变实际方案的意见，准备与核实负担可接受，并
  观察到复用或明确的继续使用理由；外部与自用证据分别陈述。
- **优先验证 D02**：评审有用，但主要负担来自反复整理背景或历史决定。
- **重排 D03 或暂停**：评审相对现有做法缺少可核实收益，或误报和核实成本
  抵消收益；记录原因后重排，不以新增面板或通用工具替代选择。
- **独立记忆产品继续候选**：跨工具记忆本身尚未在本场景证明采用理由；沿用
  044/105 的 B-lite 边界，是否扩大另据真实消费者信号裁定。

- **后续实现 ADR**：编号顺延，引用 `098/D01` 与 `110/V01–V04`；实现结果
  和试用结论分别回填，不用本次方向裁定冒充实现或需求验证。
