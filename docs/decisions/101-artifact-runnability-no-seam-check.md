## 裁定：确认缝不加产物可运行性校验

三条理由：

1. **缝的定位不符**：确认缝（L2）是「危险操作请人裁决」，不是产物
   QA。把「写完试跑一次」焊进缝里意味着——域耦合（哪些文件算测试
   类？报告、笔记、脚本的边界在哪？）、执行未经人审的产物（即使
   沙箱内，也是扩大安全面）、骨架类产物的假红（`pytest.mark.skip` /
   TODO 是合法骨架形态，跑不过 ≠ 交付失败）。
2. **量尺已在**：评测侧 verify（文件存在性）+ judge rubric（「空文件、
   伪代码或跑不起来的给 2 分以下」明码计分）已覆盖度量；生产侧产物
   由用户直接审看。缺的不是量尺，是问题持续存在的证据。
3. **证据基础失效**：n=9 红全部早于 099/100；046 纪律第一条就是不为
   已消失（或不再复现）的形状建机制。

## 登记（回填活清单，本裁定不闭信号）

活清单新条「产物可运行性无程序校验」，触发信号两条：

1. r12 型「单写薄利」任务在后续复跑中**再连续 ≥3 轮红**（099/100 前
   的形状回潮）→ 重议本裁定，第一候选是最轻的 teaching（description
   加一句「写完测试/脚本类文件建议自行验证可运行性」），不是缝校验；
2. 生产出现用户报告「agent 声称建好但产物跑不起来」→ 议 teaching 级
   自验证提示（仍非机制）。

## 边界

- 不排除未来做：信号兑现即重开；但缝校验（乙案）在可预见的证据
  形态下都不是第一候选——域耦合与假红的代价高于收益。
- 本裁定不改任何代码；r12 的质量分 3/5（骨架无真实断言思路）属
  judge 参考轴，不为参考轴调机制。
