# ADR 073：路由 stamp 与摘要决定节——Confidence Routing ⑦ 残余两件收口

- 状态：**已落地**
- 日期：2026-10-05
- 立项出处：[competitive-roadmap 9.3 #6](../internal/competitive-roadmap.md)（Confidence Routing 行动差量的最后残余，半天级）；用户 2026-10-05 盘点后批准开工
- 关联：028（场景路由）、062（收官回验——宽容校验先例）、[roadmap 9.2 ⑦](../internal/competitive-roadmap.md)

## 背景

Confidence Routing（arXiv:2609.27822）的映射留下两件残余未做：

1. **⑦③ 路由理由注入投影**：M10 single_tool 路由的决定此前只以「菜单收窄」
   间接信号存在（漂移温床）——主模型不知道路由器判了什么、不知道收窄的
   菜单在误判时可直答逃生；逃生门（028 决策 4：不强制 tool_choice）是
   有意的「允许改进」，但无「谁检查兑现」。
2. **⑦④ 摘要后程序校验**：滚动摘要的 prompt 指令层已要求保留「重要决定与
   结论」，但无程序检查——指令层裸奔（与 062 立项前 finish_plan 无回验
   同型的「承诺无兑现检查」缺口）。

## 决策

### 甲：路由 stamp（`loop.py::_route_stamp`）

- **三态文案**（direct / single_tool+工具名 / complex），程序从 kind+tool
  推导的确定性文本——Jev choice 是一段式协议，响应里没有理由字段可解析，
  **不猜协议**（伪造一个「Jev 的理由」反而失真）。
- **进投影不进底片**（时间戳/计划 stamp 同款手法）：属于「本轮视野」而非
  「对话内容」；入底片会堆垃圾、被摘要吸收。位置契约收进
  `_prepend_stamps`：时间锚点 → 路由决定 → 活跃计划，动态游标顺延补位
  （路由缺席时计划落到 2 号位而非留空洞）——三件 stamp 的组装本来就是
  一件事，收拢后 run_turn 主循环分支数不涨（PLR0912 本已满格 12/12）。
- **single_tool 回退时决定作废不注入**：Jev 选的名字不在菜单 → 回退全量、
  stamp 不注入——说收窄却给全量等于骗模型。
- **逃生门告知写进 stamp 文案**（「若判定有误可直接文字作答；工具结果回灌后
  将恢复全量菜单」）：与活清单 2026-09-29 那条「模型的菜单信念停在首轮
  窄菜单」观察项交叉——stamp 把恢复语义显式写进视野，零成本缓解。

### 乙：摘要决定节（`compressor.py`）

- `_SUMMARY_PROMPT` 加固定尾节要求：先写「【关键决定与约束】」再逐条列出
  仍有效的决定/承诺/约束，**含旧摘要里仍有效的**（滚动合并纪律——摘要
  一层层洗，上一轮的决定不许在这次合并里被洗掉，即 FR「滚动摘要洗平
  撤回」的对策）；确实没有时写「无」。
- **程序校验**：`maybe_compress` 在 `_summarize` 后做标记串在场检查；
  缺失 → `logger.warning("[摘要决定节缺失] …")` **照用不阻断**——062
  同款宽容方向，不为格式漂移付重试 token。升级前落盘的旧缓存摘要
  重组一次即自愈（warning 只会响一遍）。
- 小节文本随摘要原样进投影（`build_payload` 零改动）——对主模型是
  结构化视野增益。

## 边界（诚实登记）

- **stamp 只做「决定显式化」，不做「兑现观测」**：single_tool 下模型直答
  = 路由漂移，当前不记观测数据（漂移率可后挂 ledger 字段，挂触发信号）。
- **决定节防的是「格式洗平」，不是语义级对照**：程序检查的是小节标记
  在场 + prompt 里的滚动合并纪律，不是「某条具体决定还在不在」的逐条
  对照（那需要 P1-5 六段式摘要 + 对照源；P1-5 立项时吸收此节）。
- 路由 stamp 只影响有 router 的形态（状态A 无 key 装配缺席 → 零注入，
  原生路径投影逐字节等价，钉成测试）。
