## 背景

三轮用户输入汇成同一方向：

1. **工作使用**（2026-10-19）：VS Code 插件化、skill/MCP 配置、打断机制、
   长任务自动编排规划；
2. **通用 harness**：承接多个任务、知识库内容与使用边界需要界定开；
3. **2.0**：相比首次开源有大量功能迭代，需要统一设计而非零散加功能。

现状盘点：VS Code 壳已 ship（104，最小）；MCP 配置已齐（106）；人设硬编码
（review/brief）；打断只有取消（082①）；长任务一轮一停、无人值守与后台队列
不存在；知识全局一份（learned 三桶只认本仓、user、notes）——**多任务与多项目
的结构性隔离是最大缺口**。

## 定位（一句话）

> Facta 2.0 = 个人多任务 agent harness：把任务**委派**给它（每任务绑一个项目仓
> + 一个技能），后台长期自主推进（计划驱动、可打断、可观测），跨任务沉淀的
> 知识**按归属分层、默认最小可见**。

## 五个跨越（1.0 → 2.0）

| 维度 | 1.0（v0.9） | 2.0 |
|---|---|---|
| 交互形态 | 一问一答（run_turn 一轮一停） | 任务委派：后台长任务 + 多任务并行 |
| 控制模型 | 取消 或 等完 | 打断纠偏（steering，不杀 run）+ 分档授权 |
| 知识模型 | 全局一份 | 按归属四层（任务/项目/用户/全局）+ 可见性矩阵 |
| 能力定义 | 硬编码 mode | skill 数据化（`data/skills/*.md`），零代码加工作流 |
| 宿主 | CLI + Web 页 | VS Code 壳为一等宿主（任务面板 + 命令） |

**架构红线：2.0 不重写内核**——run_turn 的「一轮」语义、审计/确认/沙箱/围栏/
checkpoint 全部沿用；演进只发生在**编排层（调度/steering/Task）+ 数据层
（skill 文件/项目记忆）**。

## 概念模型（五层）

1. **Harness 调度层**：任务队列、后台运行、自动续跑、steering、进度与成本可观测。
2. **Task 任务**（2.0 新一等实体）：目标 + 材料 + 会话组 + 状态机 + 产物 + 分账。
3. **Skill 技能**：`data/skills/*.md` 定义人设/工具集/预算/授权档——数据不是代码，
   不触 079 红线；review/brief 迁移为首批 data skills，Brief 为首个（113）。
4. **Project 项目**：repo 锚点 + 围栏（S6a）+ 项目记忆（归属隔离，见下）。
5. **User 用户**：跨项目偏好与用户记忆（M6.5 已有）。

## 知识界定

### 归属四层（默认最小可见）

| 知识源 | 归属 | 可见性 | 写路径 |
|---|---|---|---|
| 会话历史 | Task | 本任务 | run 自然写 |
| learned 三桶 | Project | 仅绑定该项目的任务 | **仅用户确认固化**（098 红线不变） |
| 用户记忆 | User | 全部任务 | 用户编辑/确认固化 |
| notes 语料 + 图谱 | 全局 | 技能声明可见 | write_note / sync_graph（内容闸照旧） |

### 项目记忆住址（用户拍板：双模式可切）

- **默认集中式**：`data/projects/<项目>/learned/`——Facta 数据目录统一管理，
  不碰工作仓；项目登记表（repo_root → 项目条目：名称/记忆模式/路径）登记即建。
- **可切就地式**：目标仓 `.facta/learned/`——记忆跟仓库走，可进版本控制，
  换机器/换 harness 带得走（079「开放格式、可带走」精神）；切换 = 文件迁移，
  需用户确认（往工作仓写文件须显式同意，`.gitignore` 由用户定）。
- 反方登记：双模式多一档配置面（YAGNI 风险）——用户裁定工作场景两者都真实
  （公司仓不外泄 vs 个人仓要带走），可切是需求不是过度设计；实现时切换入口
  进项目设置，不做全局 env。

### 使用边界（三层防线，全部已有原型、泛化即可）

1. **能力边界**：skill 声明工具集（111 allowed_tools 先例）+ 预算（112）+
   确认档位（只读自动跑 / 涉写停 L2）。
2. **数据边界**：S6a 锚点围栏（读写限项目内）+ 052 记忆写围栏 + 敏感黑名单。
3. **知识边界**：归属四层可见性矩阵 + 固化须用户确认。

## Task 一等实体（用户拍板：完整实体）

首版即含：**状态机**（`queued → running → waiting-steer | waiting-approval |
blocked → done | failed | cancelled`）、**产物登记**（产物 = 会话/文件引用，
不新建存储）、**任务级账单**（CallLedger 已有 call_id 逐笔，Task 聚合其会话
账单；Web 壳补账单出口端点——顺带解决 111 登记的「server 无账单出口」摩擦）。

反方登记（最小起步被否）：提前抽象风险真实，但用户裁定工作使用要的就是完整
可观测与追溯，最小版很快会不够用再改更贵；缓解：账单复用 CallLedger、产物
不新建存储、状态机从 Run/Session 已有状态推导，新代码集中在 TaskStore 与
调度层。

## 分期（每期验收钉子）

| 期 | 内容 | 验收钉子 |
|---|---|---|
| **M1 可控长任务** | steering 打断 + 自动续跑 + TaskStore（完整实体）+ 任务分账 | 一个 ≥1h 真实任务无人值守跑完；中途 steering 改向一次成功；任务级账单可查 |
| **M2 界定与技能** | skill 数据化（review/brief 迁移，Brief 首个）+ 项目记忆归属（双模式） | 新增一个技能零代码；第二个项目的任务只见该项目决定；Brief 双轨对照（113 验收） |
| **M3 多任务** | 后台队列 + 任务级并发上限 + 授权档位 | 3 任务并行互不阻塞；涉写任务停 L2 等确认 |
| **M4 宿主与发布** | VS Code 任务面板/命令 + v2.0.0 + 开源发布叙事 | 壳内完成任务全生命周期操作；README/对外材料刷新 |

M1 的验收本身就是 110/V02 的自用任务（互相喂养）；V03 外部探索排在 M4 后；
098/D03（源码讲解）不进 2.0 主线，保持候选。

## 负决策（不做）

- **多用户/团队**：个人 harness，无鉴权/协作/租户。
- **in-process 插件**（079 沿用）；hooks 触发信号部分兑现（104 壳已立），
  但单独开案、不并入 2.0 大伞。
- **自动投递外部工具**（Brief 只产出不发送）；**云部署/服务化**。
- **为 2.0 重写内核**（见架构红线）。
- **多 Agent 投票/换模型保证正确性**（098 首版边界沿用）。
