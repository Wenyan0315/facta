# 决策记录 · streaming · 流式输出

> 迁自 docs/architecture.md 决策记录（2026-09-15 v0.37 拆分，内容原样保留）；append-only——修正与补充以新记录追加，不改写旧记录。返回 [architecture.md](../architecture.md)

- **streaming 流式输出（2026-09-13，独立交互层里程碑）**：把「整块回复」切成「增量流」——首字延迟从「全答完」变成「第一个 token」，tool_calls 分片重组 + 用户取消 + 网关四衣流式语义三个难题一并消化。**①接口**：`LLM.generate_stream` **默认伪流**（内部调 generate 一次吐完）——老规矩「新能力带默认实现，老代码零改动」，Mock/ScriptedLLM 免费获得流能力；`OpenAICompatibleLLM` 真流覆写（`stream=True` + `stream_options include_usage` 末班车；碎片只转增量不合并，合并归消费层）。**②生成器惰性 = 网关流式语义的全部地基**：生成器函数体在第一次 `next()` 才执行——「拿到 generate_stream 返回值」≠「请求已发出」。于是重试/降级只发生在**第一块到手之前**；第一块一 yield 字就外流、候选锁死，中途失败只能上抛（整段重试=重复说话，中途降级=前半段吐两遍），记账失败照记、熔断计数照走。**③消费层**：`merge_stream_chunks` 纯函数三件拼图——content 纯累加 / tool_calls 按 index 归并（id/name 只出现在第一块→「旧值优先」；arguments 是 JSON 碎片跨块累加）/ usage 取末班车块；`on_text` 回调把打印副作用从参数缝注入（计算与副作用解耦，本体离线可测）。拼回的 Message 与非流 generate 产物**同构**——工具执行、底片入史、usage 记账全部零感知（换件不换衣服的第五件）。**④交互裁定**：「agent：」前缀让位于首字延迟（块直打上屏，业界 CLI 惯例）；用户取消零新代码——Ctrl+C 沿既有 KeyboardInterrupt 通道 trim 半截轮+保存，生成器被 GC 时自动 close、连接沿链收尸。**⑤网关四衣的新语义**：精确缓存命中→**伪流整块**（首字延迟=0，比真流还快）、miss→转发流**不写缓存**（v1 已知边界：流式调用不投喂精确缓存，触发信号=账单命中率下降再设计「流内重建入库」）；熔断开场照旧（生成器体内、首块触发）；成功记账发生在**流耗尽时**（usage 末班车）；SemanticCache 命中伪流/miss 转发且流耗尽拼回 Message 入库（「miss 也积累条目」对流式同样成立，入库对象与外流通路隔离无污染面）；Fallback 按第一块锁候选（锁前失败随便换、锁后上抛）。**⑥验收**：测试 15 条钉死全部新语义（伪流默认/合并三件拼图/重试只在首块前/中途失败上抛且只召唤一次/熔断快速失败/非流写入流式读回缓存/Fallback 锁定不召唤备胎/语义档命中与 miss 入库），全量 107→122；真模型冒烟：deepseek 流式回答正常上屏、账单 tokens/耗时照记。已知边界：流式不写精确缓存（见上）；「agent：」前缀消失；tool_calls 碎片合并假定协议 index 字段存在。
