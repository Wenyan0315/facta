## 裁定

1. **文章＝设计取舍文，不是使用教程**：主线「为什么只有两个只读工具／为什么不给写」，素材= 044（只读裁定与理由）+ 050/052/053（内容闸/写围栏/provenance 三层）+ 096（三臂消融 84.1% vs 63.8%，+20.3pp）+ 058/103（hit@3 两轮 83–100%）。全部用已落盘读数，不新造数字。
2. **渠道＝先仓库后外发**：文章落 `docs/posts/readonly-mcp-memory-server.md`（「发布」的仓库形态，本 PR 交付）；外发（知乎/掘金等）是后续独立动作，用户过目定稿后再执行，不进本案验收。信号②观测窗从仓库版即开始（文章公开可发现）。
3. **署名＝项目名 facta**：文中以「这个项目/本项目」自述，个人完全隐身；仓库链接是唯一回流通道（issue/discussion 实测均开着——「不开 issue」的边界指不承诺运营对外支持流程，不是关闭到达通道，撒饵需要这个通道）。
4. **B-lite 内容红线（写作时逐条守）**：不开 issue、不发 PyPI、不写对外 README、不承诺 API——文章可展示挂载配置形状与真实数字，但标题下方与第 6/7 节均带「实验性出口、无任何 API 或稳定性承诺」定语；不写安装教程式承诺；隐私红线沿用——不含任何个人背景与学习目标。
5. **诚实撒饵自白**：文章第 7 节明说「这是撒饵、在等第二个用户」——B-lite 的定位在仓库 ADR 里本就全量公开，藏着掖着反而与「治理型记忆」的调性相悖；自白本身是筛选器（接受这种诚实的人才可能成为信号②的真用户）。
