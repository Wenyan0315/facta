- **产品定位裁定（2026-09-16，「先产品设计还是先规划 agent」讨论的产物）**：方法论裁定——**不做瀑布式产品设计先行**（需求方=用户本人，dogfooding 即需求验证；五轮真实使用修复证明「活 spec」在起作用，每个 bug 都是「用了才炸」），但补**一页纸产品锚点**治「无锚」病：此前 roadmap 纯工程视角（技术依赖驱动），「任务」语义未定义、真实使用在漂移（通用助理 vs coding agent 叙事）。**定位裁定：通用个人 agent**——能力通用、锚点在「个人」（单用户）；三场景并列（知识伴侣/个人助理/工程协作），优先级由真实使用数据动态排序，不预先垂类化（定位与能力分离：定位决定围着什么转，不是能力上限；垂类化留给真实使用把某场景顶成主要矛盾时再收敛）。**任务语义**：个人待办（UI 创建/勾销，agent 可读写），工程委派归 S4/S6。**当日排期**：联网优先（两次实测失败的核心缺口）→ 时间戳顺手修 → 待办下一轮。证据台账随归档更新（product.md）。连带裁定：**联网工具排期前置于 S3**——「先栅栏后开门」原则下联网属「开门」类能力，提前开门的最低防护（只读 GET/超时/私网地址拒绝）随工具一并落地，完整栅栏仍归 S3。
