# ADR 088：待办 ID 复用与持久化风险修复（持久化递增 ID + 原子写 + 坏 JSON 保全）

- 状态：**已批准**
- 日期：2026-10-06
- 立项出处：[087/R01](../decisions/087-project-review-and-next-priorities.md)
- 关联：016（待办语义）、071（数据目录与稳定 ID）、087（项目评审）

## 背景

087/R01 落点 [memory/todos.py](../../src/facta/memory/todos.py)，复现与读码确认三处缺陷：

```text
add("old task") -> id=1
delete(1)
add("new task") -> id=1   # 旧引用指向新任务
```

1. **ID 复用**：`add` 用 `max((t.id for t in todos), default=0) + 1` 分配身份，
   删除最大编号或清空列表后旧 ID 会被重新分配——id 是引用键，复用＝悬垂引用
   （016 已裁定「id 空洞不复用」，但 `max+1` 实现保证不了「删除最大编号也不复用」）。
2. **非原子写**：`_save` 直接 `write_text` 覆盖文件，写一半崩溃留半截坏文件。
3. **坏 JSON 静默覆盖**：`_load` 遇 `JSONDecodeError` 返回 `[]`，后续 add 会把
   原数据静默覆盖——坏文件里原有的待办在不知情中丢失。

## 拍板

### ① 持久化递增 ID（`next_id` 计数器）

文件加 `next_id` 字段，与 `todos` 同级持久化。`add` 用当前 `next_id` 分配、落盘时
写 `next_id + 1`。删除最大编号后 `next_id` 不回退，旧 ID 永不指向新任务。

选「持久化递增 ID」而非 UUID：016 已裁定「id 自增、对模型友好（念不全时间戳/散列）」，
保持既有引用键形状不变、兼容存量数据；UUID 会推翻 016 的模型友好性裁定且无新增收益。

### ② 原子写

`_save` 改为写同目录临时文件 + `Path.replace`（POSIX 下 `os.replace` 语义，原子替换），
崩溃不落半截文件。

### ③ 坏 JSON 明确报错，保留原文件

新增 `CorruptTodoFile` 异常。`_load` 遇 `JSONDecodeError`（或解析结果不是 dict）抛
该异常，**不再返回空列表**——任何读/写路径都停在原文件上，不做覆盖；调用方据此
知道数据没丢、需要人工处理。旧格式（`version` 1，无 `next_id`）迁移：`next_id` 由
`max(id) + 1` 推导，存量待办逐字节保留。

## 重新裁定 016

016 曾裁定「损坏文件当空仓（待办非关键数据，不炸入口）」。087 判定该口径的风险
（坏 JSON 被当空仓后，下一次 add 静默覆盖原数据）压过「不炸入口」的收益——坏文件里
的待办是用户资产，宁可明确报错让人处理，不可当作不存在。**本条推翻 016 的「损坏当
空仓」口径，其余 016 语义（id 空洞不复用、勾销/删除/修改三分、单实例注入）不变。**

## 边界（诚实登记）

- **原子写不提供跨进程互斥**：`todos.py` 仍是进程内 `threading.Lock`（个人工具量级、
  单实例注入，与 016 一致）；临时文件用固定名，多进程同时写会互相覆盖 tmp，但
  `Path.replace` 保证每个进程要么落完整文件要么保留旧文件。跨进程待办并发不在本轮
  范围（触发信号＝出现多进程写待办需求时，参照 SessionStore 的 flock 方案）。
- **坏 JSON 无法自动恢复**：明确报错后仍靠人修文件（或删掉重建），不做逐字段抢救——
  JSON 结构都坏了时自动抢救会引入「猜错数据」的新风险，与 045/064「记忆不可逆资产
  保守方向」一致。

## 验收

- 删除最大编号后 `add` 不复用旧 ID（`add→1, delete(1), add→2`）。
- 删除中间编号后不回填空洞（`1,3` 后下一条是 4），`next_id` 跨 reload 持久化。
- 旧格式文件（无 `next_id`）迁移后 `next_id = max(id)+1`，存量待办保留。
- 坏 JSON：`list()` 抛 `CorruptTodoFile`，原文件字节未被改动。
- `_save` 后无 `.tmp` 残留；写入内容含 `next_id`。
- 既有待办测试全绿（除「损坏当空仓」断言按本条翻转）。
- 三门通过（ruff / mypy / pytest）。
