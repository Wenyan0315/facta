# ADR 074：learned 四态 tombstone——删除留「已撤回」，腐化/重复走出口闸门

- 状态：**已落地**
- 日期：2026-10-05
- 立项出处：[competitive-roadmap P2-1](../internal/competitive-roadmap.md)（记忆补全三件套之一：删除留 tombstone，FR 四态状态字段）；用户 2026-10-05 裁定「完整四态全做」
- 关联：032（记忆系统原则）、045（易腐事实入口闸门——本案是其反方4「只治入口不治出口」的补课）、053（provenance 行内 tag）、071（稳定 id）

## 背景

固化管线只有「追加」没有「撤销」：面板删掉一条，下轮 consolidate 的
`_load_known` 把原行喂给内部 LLM 当「已知记忆」时，模型看到的是「这条还
在」，会再记一遍——**删除被复活**。反向地，已入库条目一旦腐化（行号/计数
这类几天就失效的易腐事实漏网入库）或与新条目重复，也**没有任何出口**：
045 只治入口不治出口，立项时明确把「出口闸门」推迟为本案。

FR（Fortunate Recall）四态给出现成数据模型：
- **在用**（active）：正常召回/注入
- **被取代**（superseded）：被更新的同事实条目取代
- **已过期**（expired）：时效性失效（易腐事实到期）
- **已撤回**（retracted）：人主动删除
每态带**事件时间**字段（哪一刻进入该态）。

## 决策

### 甲：状态编码——沿用行内 tag 而非 sidecar

四态不另建 sidecar 表，状态写成行内 tag `[已撤回:YYYY-MM-DD]`、
`[已过期:YYYY-MM-DD]`、`[被取代:YYYY-MM-DD]`，与 053 的 `[固化:sid]` 同一
机制：状态名 + 事件时间同落一个 tag，闭集词表（只这三个前缀），落盘可 grep；
给模型看的 `render`/`visible_text` 自动滤掉（不在 `VISIBLE_TAGS` 里）。
「在用」= 无状态 tag（零迁移：存量行天然在用态）。理由：053 已确立「tag
词表闭集 + 单份真值由常量拼正则」，sidecar 是第二份真值，会漂。

### 乙：删除语义——物理删除改「已撤回」tombstone

`delete_line`/`delete_line_by_id` 不再 `del lines[line]`，改给好行打
`[已撤回:今天]`；坏行（手写裸行）仍物理删（无日期无 tag，打不上 tombstone
也没意义）。tombstone 保留原正文与 id——`_load_known` 读原行仍能看见「这条
被撤回了」，模型不再复活它；`read_learned` 默认过滤非在用，面板/注入/召回
自动不再看见它。

### 丙：读侧过滤零改动

`read_learned(path, include_inactive=False)` 默认只回在用态。所有消费点
（agent 注入、plan 召回、面板 GET）都走 `read_learned`，靠默认参数一次过滤，
**消费点零改动**。`_load_known` 保持读原行文本（含 tombstone）——这正是
防复活的关键，若它也改成 `read_learned` 过滤，删除又会被复活。

### 丁：出口过期走规则层，不花模型

`consolidate` 每条管线先扫在用条目命中 045 的 `_PERISHABLE_PATTERNS` →
打 `[已过期]`（`_expire_perishable`）。纯正则、零模型调用，与 045 入口闸门
复用同一份正则（单份真值）。承接「已入库条目腐化无出口」痛点，也是 recall
x-ray「陈旧率」（P2-1 ②件）的数据来源。

### 戊：被取代走模型语义检测（有存量才触发）

`_supersede_duplicates` 按作用域（project/user）分桶，把「本批新条目」与
「该作用域在用旧条目（带序号）」喂给模型，模型回要打「被取代」的旧条目
序号 → `set_statuses` 批量打 `[被取代:今天]`。**只有该作用域既有在用条目
又有新条目时才花一次模型调用**（fresh 目录零调用）——刻意的省 token 触发
条件：现有 ScriptedLLM 测试（2 条脚本）在 fresh 目录下不受影响。

## 边界（诚实登记）

- **被取代要花模型**：与 roadmap「过期过滤走规则层、不花模型」的字面约束
  冲突——但「不花模型」在原文限定的是**过期**过滤，被取代是语义重复检测、
  无规则可判。用户已裁定接受此冲突，换取取代的语义质量。
- **取代检测不跨作用域**：project 与 user 分桶独立检测，同一事实两边都记
  不会互相取代（那是双份噪音，045 入口闸门管）。
- **过期是保守扫**：只拦 045 正则能匹配的明确形态，语义级「这事实过时了」
  不在规则层判（那是模型的事，当前不做，挂触发信号）。
- **tombstone 会留盘**：被撤回/过期/取代的行仍在文件里（只是被过滤）——
  文件随删除累积，但换来「可审计 + 防复活」；真要物理回收是 P2-2
  sleep-time 整理的活。

## 验收

三门全绿；新增 tombstone 相关测试：delete 改撤回、读侧过滤、过期规则层、
取代模型检测、越界/幂等边界。

## 触发信号

- 需要「陈旧率」（top-k 里过期/被取代占比）→ recall x-ray（P2-1 ②）在此
  数据上计数
- 「某事实语义过时但正则没拦到」的实例累积 → 议语义级过期检测（花模型）
- tombstone 行堆积 → 议 sleep-time 物理回收（P2-2）
