# 决策记录 · ACI 工具反馈规范 + mini 回归基线（2026-09-24）

> 竞品对标 P0-2 立项：工具反馈设计是被实证的成功率杠杆，同时引入 bash-only 基线防「机制虚荣」。返回 [architecture.md](../architecture.md)

- **来源与依据**：SWE-agent 的 ACI 研究（NeurIPS 2024）实证——窗口化文件查看 + edit 后 lint 反馈等接口设计，使 SWE-bench 解决率相对裸 bash 接近翻倍，「界面即模型」；mini-swe-agent 反证——~100 行、仅 bash、线性历史、独立 subprocess 的极简形态仍达 65% SWE-bench Verified。两相对照的结论：工具反馈设计值钱，脚手架复杂不值钱。cortex 现状：文件查看/搜索工具反馈未规范化（空输出无显式标记、查看无分页、搜索喷全文），evalkit（024）无外部参照基线。本条为竞品对标红队版「烂尾也值」最小集之一（另一条见 038）。

- **四拍板**：
  - **P1 文件查看分页化**：~100 行窗口 + 「上方 N 行 / 下方 M 行」上下文指示（SWE-agent 同款形态）；窗口大小可配置，默认 100。
  - **P2 空输出显式化**：所有工具的空结果必须返回显式「无输出」标记，消灭「空输出=工具坏了还是真没有」的幻觉温床。
  - **P3 搜索默认文件清单**：搜索工具默认只返回有匹配的文件列表 + 命中计数，全文/上下文按需二次展开（防一次搜索喷爆上下文）。
  - **P4 mini 基线固化**：evalkit 内置一个 bash-only 迷你 agent 配置（仅 bash 工具、线性历史、每步独立 subprocess，mini-swe-agent 形态）作为**永久回归基线**；任何执行类机制（hooks、ACI、模型分层……）评审时必须回答「同场景比基线好在哪、贵多少」。

- **反方意见（037 起每篇决策强制本节）**：
  1. **场景外推风险**：ACI 证据来自 SWE-bench 代码任务，cortex 是个人通用助手，收益未必平移——应对：规范落地前后在自建场景集做 A/B，数据不达标就回滚单条规范，不一揽子硬上。
  2. **分页的轮次成本**：窗口化可能增加「翻页」轮次——应对：轮次与 token 双指标同时度量，只要总 token 降、解决率不降，轮次上升可接受。
  3. **基线误杀风险**：记忆类机制对 bash-only 基线天然「不公平」（基线没有记忆可挂）——应对：基线对比仅用于执行类机制评审；记忆类机制走召回命中率/注入成本指标（032 体系），不与基线比。

- **触发信号（未达即不扩编）**：本规范四条落地后，若自建场景集「总 token 下降且解决率不降」不成立，冻结后续 ACI 方向投入，回查假设。

- **验收**：evalkit 自建场景集 A/B 报告（前后对比）+ mini 基线一键可跑并出分；pytest / ruff / mypy 三道门全绿；实机轮抽 3 个真实任务人工对比反馈可读性。
