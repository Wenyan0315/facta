# 决策记录 · S4b 终端执行 + L2 确认机制（2026-09-17）

> coding agent 的手（执行侧）；S3 判据的主场。返回 [architecture.md](../architecture.md)

- **S4b 落地（草案评审通过后兑现，S4 整体收官）**：**①run_command（tools/terminal.py）**——subprocess shell=True、cwd 锚定 WORKSPACE_ROOT、超时 60s kill、输出 6000 字截断、exit code 如实回传；shell=True 是裁定不是疏忽（管道/重定向是刚需，危险面由确认机制兜住，不在工具内做命令解析）。**②白名单免确认（粒度裁定：用户三选一拍板「只读命令白名单」，弃全量确认）**——双条件缺一即弹窗：主命令在白名单（纯读取单命令 / git 只读子命令 status·log·diff·show / python 仅 `-m pytest`）**且**整串不含 shell 元字符 `;&|><\`$()` 及换行；`needs_confirm` 纯函数成测试靶子，绕过用例专打（`cat x; rm y`/`git status && evil`/`$(evil)`/`ls\`evil\``/换行夹带/`FOO=1` 环境变量前缀/sudo/git push/python app.py）；拿不准就确认——误弹窗代价一次点击，误放行代价不可控。**③确认缝开在 registry 而非 loop（S3「写入点=execute 单一必经点」承诺保持）**——Tool 加 `needs_confirmation` 元数据（bool 或 callable(args)），execute 执行前裁决，loop 只透传 `on_confirm`（与 on_text/on_event/should_cancel 并列第四条缝，CLI 挂 input、Web 挂 Event.wait）；**批准与拒绝都自动落审**（拒绝也留痕——事后可查「谁在什么时候想干什么」）。**④保守默认三连**：Tool.is_readonly 默认 False；无 confirm 通道时标确认的工具按拒绝处理（没有眼睛就不动手）；CLI 只有显式输入 `y` 才批准（空回车/任意非 y 都算拒）。**⑤Run 状态机扩展**：waiting_approval 首个非终态扩展（活跃态，进 _IN_FLIGHT 单锁口径——挂起等确认也算在跑）；request_confirm 阻塞 worker 线程、confirm.request/confirm.resolved 进 append-only 事件流（断线重放时 request 无 resolved 配对则前端重弹，确认不随断线丢失）；等待中可取消（取消视为拒绝，确认挂起不挡取消通道）；Web 端点 POST /api/runs/{id}/confirm（无挂起 409）+ 前端弹窗（命令全文展示）。**⑥拒绝不炸会话**：拒绝结果串「用户拒绝了这次操作…请换方案」作为 tool 消息回灌模型，可换方案继续（实测：被拒后如实汇报+给替代方案+不重试同一命令）。**⑦SYSTEM_PROMPT 自我画像同步**：终端工具上桌+负面清单删除「没有终端执行能力」。剪裁（触发信号）：输出实时流不做（长任务出现时上）——echo 命令等完拿全量输出 v1 够用；确认无超时（可取消兜底）——用户晾着就晾着，超时自动拒会把「离开一会」变「全拒」；白名单残留风险如实记：pytest 可执行任意逻辑、`python -m pytest` 免确认是开发循环的便利换防护的让步，硬线仍是审计+确认弹窗兜底其余。验收：测试 229→286（needs_confirm 白名单 13 例+绕过 21 例；执行六用例 echo/exit code/超时/截断/cwd/危险命令被拦；confirm 流批准/拒绝回灌/拒绝落审/无通道默认拒/默认 False 工具不受影响；loop 缝透传；CLI 缝 y/非 y；状态机挂起/取消视拒/无挂起 409 判据/单锁口径；API 端到端批准流+拒绝流）；浏览器三流实测（非白名单+批准→文件落盘+审计 exit code 0 / 非白名单+拒绝→文件未建+拒绝落审+模型换方案 / 白名单 git status→直通无弹窗），审计 jsonl 佐证；验收顺手修一 bug：弹窗参数显示 [object Object]（事件里 arguments 已是对象，前端却当 JSON 字符串再 parse——命令全文没露给用户，裁决依据缺失）。
