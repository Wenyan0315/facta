## 背景与动机

承诺漂移论文（roadmap 第 9 节⑦）的三问审计——谁做了决定／谁真正执行了／执行时还是原来的决定吗——在固化管线上的逐条对照：

1. 萃取（档案员）产出候选 = **决定**；
2. 审查（critic）落盘前把关 = **执行**；
3. 现行 `REVIEW_TEMPLATE` 的口径是「可以修正措辞使条目更忠实于原文」——**执行时决定可以被悄悄改掉，且改成什么样无任何记录**。落盘行上分不出「原样通过」与「被审查重写」。

P0-7 已落地的部分（`c57ef76`：verified 字段 + 背书硬校验 + 无背书降级候选）管的是「**条目内容**可不可信」，本案管的是「**审查动作**本身可不可信」——两条是不同的缝，前者已焊，后者从 2026-09-25 合并第 7 篇论文起挂账至今。

时机依据：P0-5 四子件（[060](060-plan-failure-ledger.md)/[061](061-plan-context-memory-recall.md)/[062](062-plan-delivery-verification.md)）与 P0-8 配套（[053](053-memory-provenance.md)/[057](057-plan-tool-scope.md)）已于 2026-09-28 全部收口，终版表 P0 行只剩这一件未动；[063](063-eval-harness-answer-sheet-isolation.md) 已批准待动工，本案排在其后（WIP=1）。

## 地面真值（写代码前核对，全部读码取证）

1. **管线形状**：`consolidate()`（`src/agent/memory/consolidate.py:302`）＝萃取一次 LLM 调用 → `_parse_json_array`（:168，剥围栏容错）→ 审查第二次 LLM 调用 → 同一个 `_parse_json_array` → `_harden`（:202，程序闸）→ `_append`（:251）。两次生成之间唯一的物化是 `entries_json` 字符串——**它是瞬时的**，不进任何落盘物。
2. **审查口径原文**（:105-122）：「找得到依据的保留；找不到的删除／**可以修正措辞使条目更忠实于原文**，但禁止添加原文没有的信息／重复的条目只留一条」——自由重写是**被现行提示词明文授权**的，不是模型自作主张。
3. **`Entry` 无 id 字段**（:125-130：category/content/scope/verified）——萃取与审查之间的条目身份靠**数组顺序**隐式对齐，审查删一条后顺序即错位，想对账都对不上。
4. **代码闸在后、语义闸在前**：`_harden` 管形状（敏感凭证／易腐／长度／类别白名单／批内去重／P0-7 缺背书降级），无论审查输出长什么样都照过——**edit 再自由也绕不过代码闸**，本案要收的只是「改写留痕」，不是「改写放行」（那是 `_harden` 已有的职责）。
5. **报告通道现成**：`consolidate` 返回报告串（CLI 打印、Web 忽略），`_brief`（:291）已有「拦截报出原文」的惯例（045 易腐／P0-7 缺背书都走它）——edit diff 进报告是同款手法的自然延伸；但报告串**是瞬时的**（会话级打印，不落盘），「落盘可查」需要另找 durable 落点。
6. **durable 留痕的现成先例**：[053](053-memory-provenance.md) 的 notes sidecar（`data/notes/.provenance.json`，落 052 围栏内、kb 索引与 `list_notes` 都看不见、gitignore 后 `git archive` 副本天然不带）——「程序写的、伪造不了的旁证文件」这套形状已被实测证明无回归面。
7. **可见 tag 词表是闭集**（053：`_TAG_PATTERN` 由 `VISIBLE_TAGS` + `ORIGIN_TAG_PREFIX` 拼出）——给落盘行加任何新 tag 都要过那套纪律；本案**不碰行格式**（零迁移、零注入面变化，053 的 `tokens_in` 逐字节不变式证据链不受威胁）。
8. **解析器教训在案**（[062](062-plan-delivery-verification.md) 实现期偏移①）：复用现成解析器前必须读它的真实行为——`_parse_json_array` 返回 `(条目, 是否解析成功)` 双态，「明确空数组」与「坏 JSON」已分开（这正是它存在的理由），审查输出的新 schema 复用它时**元素形状校验要新写**（它只保证 list[dict]，不保证字段）。
9. **既有测试基线**：061 时三门 695 passed；consolidate 相关断言 60+ 条按现有 `_parse_json_array` 双态与 `_harden` 行为写成——新 schema 必须**宽进**（旧自由格式输出仍可解析入库），否则一夜全红（050 改 `expect_tools` 口径的同款教训）。

## 设计（三件，◆ = 待用户裁定）

### ① 萃取侧：条目 id 物化

`EXTRACT_TEMPLATE` 输出格式加 `id` 字段（档案员自编 `e1/e2/...`，提示词写明「只作对照锚，无语义」）。程序侧校验：id 缺失或重复 → 该条归 `drop` 并记原因（**身份都物化不了的条目，没有资格进入「决定→执行」对账**；与 scope 非法归 project 的垃圾桶方向不同——身份缺失不是「放错位置」，是「无法对账」，保守方向＝弃）。

### ② 审查侧：裁决枚举化

`REVIEW_TEMPLATE` 输出改枚举裁决：`[{"id": "e1", "verdict": "keep|drop|edit", "content": "…（仅 edit 必填）"}]`。措辞修正从「明文授权的自由重写」收窄为「**必须显式声明 edit 并给出改后全文**」——改写从默认动作变成显式动作。程序侧规则：

- `keep` → 取**萃取原文**进 `_harden`（不信审查回抄的 content——回抄本身就是一次再生成，可能漂移；id 物化的意义正在于能回去取原文）；
- `drop` → 弃，原因进报告（与现行「审查驳回」计数合并）；
- `edit` → 取审查给的 content 进 `_harden`（代码闸照过，敏感／易腐／长度一条不免），**diff 留痕**（见③）；
- id 对不上萃取清单（编造 id）→ 该裁决整案弃＋记「审查幻觉」——这是枚举化白送的幻觉探针：自由格式时代「审查编一条新条目」与「保留一条」不可区分，现在结构性可分；
- ◆ **拍板 1（非法 verdict 的处置）**：甲＝归 `drop`（推荐：记忆是不可逆用户资产，045「易腐入库不可逆污染」同款保守方向；审查连裁决都表述不清时，条目命运不该交给猜测）；乙＝归 `keep`（萃取已过一次档案员，审查没说出 drop 就不替它丢）；丙＝归「候选」通道（复用 P0-7 缺背书那条的「报告列出待二次确认」——但两条原因混报会误判，050 已立过「不混报」先例，不推荐）。
- ◆ **拍板 2（旧格式宽进）**：甲＝宽进（推荐：审查输出缺 `verdict` 字段的旧形状按 `keep` 处理＋报告标注「审查输出为旧格式」——061 基线 695 条测试零改写，与 learned 坏行宽容、Entry.scope 缺省兼容同族）；乙＝严进（旧格式整案拒，重试一次再拒则本轮固化放弃——更干净但既有断言要翻一批，且「模型偶尔不听话」从留痕事件变成丢记忆事件）。

### ③ 留痕侧：edit diff 落盘

- 瞬时层：`_brief` 同款进报告串（「e2 经审查修改：原文 → 改后」，截断各 60 字）；
- ◆ **拍板 3（durable 落点）**：甲＝`data/learned/.review.jsonl` sidecar（推荐：053 的 `.provenance.json` 同款形状——append-only、程序写、落在 052 `MEMORY_WRITE_FENCE` 内伪造不了、gitignore、评测副本天然不带；每行 `{ts, sid, id, verdict, before, after}`）；乙＝只进报告串（零新文件，但「落盘可查」降级为「当时打印过」——045/050 的教训是瞬时报告事后对不上账）；丙＝写进 learned 行内 tag（**明确否决**：撞 053 闭集词表纪律，且 `[审查改]` 进注入 prompt 是噪音不是信息——053 的 tag 二分里它连「给排查看的」都不够格，因为排查要的是 diff 全文不是一个标记）。

## 反方意见（强制小节）

1. **「审查改措辞是 feature 不是 bug」**：忠实化修正（剥易腐尾巴、压缩冗长）正是 critic 的价值，枚举化 + 留痕是在给正常动作加税。回应：不禁止 edit，只要求**显式声明 + 留痕**——忠实化修正照旧合法，变的只是「无痕」变「有痕」。成本是审查提示词几十字 + 程序校验几十行，不是流程改造。
2. **「id 物化防不住真正的漂移」**：模型可以一边输出 `verdict: keep` 一边指望回抄——哦不，keep 取的是萃取原文（设计②已堵）；那模型可以 `edit` 一个面目全非的 content 再编个「忠实化」理由。回应：对，枚举化不消灭语义层漂移，它消灭的是**无痕**——edit 的 diff 落盘后，「审查改写幅度」第一次成为可度量对象（grep `.review.jsonl` 统计 edit 占比与编辑距离），漂移从「不可观测」变「可观测」，这是所有后续治理的前提。与 050 归因仪器同哲学：先能测，再谈治。
3. **「为一条 n=1 项目、每天未必触发一次的管线建审计设施是过度工程」**：固化管线 6 天真实使用里触发次数有限（CONSOLIDATE_THRESHOLD=20 条消息一跑）。回应：这是**半天级**改动（roadmap 9.3 自估），且它是 044 挂账的 `memory_add` 开闸前置链条上的一环——写路径一旦对 MCP 开闸，「谁改过条目」就从内部洁癖变成外部接口的诚信问题；趁流量小把仪器建好，比开闸后补账便宜。
4. **「sidecar 又添一个真值源」**：`.review.jsonl` 与 learned 行可能漂移（行被面板编辑/删除后，sidecar 里的 before/after 对不上）。回应：sidecar 定位是**事件日志**不是状态镜像——它记「某时某刻审查做了什么」，不承诺与当前 learned 内容一致（与 audit jsonl 同语义：审计也不因文件被删而失效）。053 的 sidecar 已立同款先例。
5. **「拍板 2 宽进是养坏习惯」**：旧格式按 keep 放行，模型永远学不会新格式。回应：报告里标注「旧格式」就是留痕——出现频次可观测，真成习惯再收紧（触发信号：旧格式占比目视过半）；一上来严进则是拿 695 条既有测试的稳定盘赌提示词服从度，046 纪律不赌这个。

## 验收标准

- 枚举审查后：edit 裁决的 diff 进报告串 +（若拍板 3 选甲）`.review.jsonl` 各一份；keep 条目与萃取原文**逐字节一致**（程序保证，不靠模型回抄）；编造 id 的裁决被弃且记「审查幻觉」。
- 宽进（若拍板 2 选甲）：旧自由格式输出照常入库，报告标注；061 基线 695 条测试**零改写**全绿，净增测试只加不改。
- 两道假红守卫写成测试（050 同款纪律）：①「审查 edit 后的内容含敏感凭证」→ 照样被 `_harden` 拦（edit 不能绕过代码闸）；②「合法忠实化修正」（剥易腐尾巴）→ 正常入库且留痕。
- 估时：**半天**（模板两句 + 校验约 60 行 + sidecar 约 20 行 + 测试约 6 条）；三门全绿；不动 `learned.py` 行格式、不动 `_harden` 规则、不动 053 任何 tag。

## 触发信号与边界

- 宽进收紧为严进：旧格式输出占比目视过半。
- 「审查改写幅度」治理（如下一步）：`.review.jsonl` 攒满约 50 条 edit 记录后做一次人审复盘，决定要不要给 edit 加「改写幅度上限」——现在不加，无数据定不了阈值（032「文件数>10」死信号同款教训）。

### 实现期偏移（以实现为准）

- **「id 缺失归 drop」放宽为「程序按序补位」**：草案 ① 写「id 缺失或重复 → 该条归 drop」，实现只保留**重复**归弃；缺失由程序补位 `e1/e2/…`——拍板 2 甲的验收标准是「061 基线既有断言零改写」，而全部既有测试的萃取脚本都不带 id，一字不改就必须宽进；且程序铸的锚同样确定，身份由谁铸造不影响对账语义（补位撞上模型已用的 id 时加下划线让位）。

- **未获裁决的候选归弃**：草案只写了「审查没说出 drop」的争点，未明说「完全没提」的处置；实现按拍板 1 同方向归弃并记数（审查没说 keep 就不替它留）——旧格式的「保留清单」语义下这不发生（不在清单＝被 drop，行为不变）。
