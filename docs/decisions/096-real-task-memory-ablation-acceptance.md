# ADR 096：真实任务与记忆消融验收——三臂对照（完整 / 无记忆 / bash 基线）

- 状态：已验收（2026-10-06，三臂 × 3 轮正式出分，结果见「验证结果」节）
- 日期：2026-10-06
- 上游：[087](087-project-review-and-next-priorities.md) R06（真实任务与记忆消融验收）、[046](046-frozen-real-task-eval.md)（冻结集与双臂 runner）
- 推翻关系：无新增（046 全部纪律沿用）

## 背景

087 给 R06 的定义：选 10–20 个实际任务，对比完整系统、关闭记忆、bash
基线；记录完成率、成本、耗时、人工介入次数，关键题重复运行；保持模型、
任务和预算等对照条件明确，记录失败和副作用。087 补注又点了名：现有记忆
消融（memory_ablation.py）只证明**闭卷召回**收益，不证明**执行成功率**
收益。

046 已把「双臂同源对照」的基础设施建成（git archive 副本、案卷隔离、
五件套硬断言 + LLM-judge、轨迹对齐），且历史出分留下一个未竟问题：
full 臂唯一的机制性净胜只有 r7（seed 记忆 + 冷僻指纹）一条——样本太薄，
「记忆对执行成功率的收益」这个 R06 核心问题回答不了。两个关键事实决定了
本 ADR 的形状：

1. **副本天然没有 learned 记忆**：`data/memory/` 完全不入 git，
   `data/learned/` 在库内只有一个 example 模板。full 臂的记忆几乎全来自
   场景 setup 的 seed——所以「关记忆」臂的实现 = 把 seed 也抹掉，而不是
   去改装配代码。
2. **素材池足够**：2026-09-27 以来真实会话 13 个，可新采「记忆应受益」
   任务，把 r7 式对照从 1 条扩到 6 条。

## 裁定

1. **三臂同源，新增 nomem 臂只动 harness 不动场景**：
   `full`（完整装配）/ `nomem`（完整装配、副本记忆层抹除）/ `bash`
   （既有基线）。实现全部落在 frozen_eval.py：
   - `_wipe_memory(wt)`：删 `data/learned/` 整个目录 + 删
     `data/user-memory.md`（FACTA_USER_MEMORY 锚点）。调用时点卡在
     `_stage_scenario` 之后、`_spawn_child` 之前——**setup 照跑，seed
     落了也抹**。哪些 setup 算「记忆 seed」不该由评测器逐题判断；
     统一后抹，staging 与 full 臂逐字节同源。
   - notes / 向量库 / 图谱**保留**：那是知识库（语料资产），不是记忆
     （用户裁定口径）。抹知识库会把「记忆收益」与「语料收益」混在一起。
   - 运行中的固化写回**不关**：两臂同一套机制，被隔离的变量只是
     起跑线上的记忆资产。
   - 子进程零新增代码路径：`mode == "nomem"` 走 `_full_arm`；
     `_grade` 的 `check_mechanism` 改为 `mode in ("full", "nomem")`
     ——nomem 只缺记忆，计划/确认缝/工具族全在，机制断言照常判。
   - CLI 加 `--nomem`（与 `--baseline` 互斥），落盘文件名前缀
     `nomem-`，汇总行标签「无记忆臂」。
2. **任务集 = 老 18 条原样 + 新采 5 条（r8–r12）**，冻结进
   `evals/scenarios/frozen_real.jsonl`。老题一字不动（046：不为分数
   改题）。新题全部出自 2026-09-27 后的真实会话，每条带 `source`
   出处，各覆盖一种记忆类型：

   | id | 记忆类型 | seed 落点 | 指纹（answer_contains） | source |
   |----|---------|-----------|------------------------|--------|
   | r8-weather-city | 用户事实 | user-memory.md | `上海` | 20260929-095616 |
   | r9-rag-followup | 进行中事项 | learned/other.md | `语义检索链路` | 20260929-114434 |
   | r10-baba-update | 产物增量更新 | user-memory.md | `110.00` | 20260929-115502 |
   | r11-php-role | 冷僻决策原话 | user-memory.md | `工具层` | 会话群 system 记忆块 |
   | r12-inv-naming | 冷门命名约束 | learned/constraints.md | `inv_` | 会话群 system 记忆块 |

   指纹纪律沿用 r7 模板：**seed 必须含冷僻指纹、任务文本必须不含**，
   且指纹不得出现在考场语料（data/notes、src、tests）里——本 ADR
   写作时已逐一 grep 验证为零命中，否则 nomem/bash 臂能瞎猫碰上，
   区分度归零。
   开发轮（正式冻结前）两处修正：① learned 注入只认
   decisions/constraints/other 三桶白名单文件名，r9/r12 的 seed 从
   自命名文件挪进白名单桶（r9→other.md、r12→constraints.md），否则
   full 臂也读不到 seed；② r11 指纹从原话 `php作为工具吧` 放宽为
   `工具层`——模型援引决策时改写原话是正常行为，逐字指纹会把「记得」
   误判为「没记得」。
3. **新题允许开发轮，正式开跑即冻结**：r8–r12 允许用 `--only` 小预算
   试跑到「seed 注入可读、指纹两臂可分」为止（属题目开发，不算为分数
   改题）；三臂正式出分一旦开始，题面冻结，后续只加新题不改旧题。
4. **重复运行 = CLI 层跑 3 轮，不加 --repeat**（Ponytail：shell 的 for
   能做的事不进代码）。三臂 × 3 轮 = 9 份落盘 JSON，机制结论需 ≥3 轮
   同形态证据（046 偏差 5 的执行件），单次出分不驱动任何机制改动。
5. **预算 ¥20 硬顶进代码**：`--budget` flag（默认 0 = 不限），每场景
   结束后累计「被测账本 + judge 账本」，超顶即打印已花费并中断批次
   （已落盘的读数保留）。历史出分单价（¥0.26/10 题）外推 23 题 × 3 臂
   × 3 轮 ≈ ¥5–8，硬顶是保险不是预期支出。
6. **判定标准**（087 四指标 + 两条判据）：
   - 四指标三臂对比：完成率、成本、耗时、人工介入次数（judge 质量分
     照旧只作参考，不进 pass/fail）。
   - **臂有效性判据**：r7–r12 六条 seed 场景上 full 必须显著优于
     nomem（指纹命中率）。若 full ≈ nomem，说明记忆注入链没生效——
     那是产品 bug，不是「记忆无用」的证据，先修链再谈结论。
   - **执行收益判据**：full vs bash 在老 18 条执行型任务上的完成率差，
     才是 R06 要回答的「记忆/机制对执行成功率的收益」。
7. **记录失败和副作用**：每轮的 fails、污染命中（_contaminated）、
   围栏触发（_guards）随 JSON 全量落盘，汇总进「验证结果」节——
   不只报通过率。

## 边界（显式记录）

- 任务集封顶 23 条，不扩 50/100；不接 SWE-bench 等外部基准（046 同款）。
- 不改记忆机制本身：本 ADR 只产出「记忆有没有用、值多少」的证据，
  机制改动是看出分之后的后续 ADR 的事。
- 不为分数改题；不为让三臂「拉开差距」而调 seed——分叉不足先查注入链。
- 不建 CI 定时跑（真实 LLM 烧钱，手动触发）；不造新 runner。
- nomem 臂语义 = 「零记忆资产起跑」，不是「记忆系统不存在」——固化
  写回、召回代码路径两臂完全一致。

## 验收（087 的 R06 完成标准，逐条）

- [x] 10–20+ 实际任务三臂对比（18+5=23 条 × full/nomem/bash）。
- [x] 记录完成率、成本、耗时、人工介入四指标。
- [x] 关键题重复运行（全题 3 轮）。
- [x] 对照条件明确（同 provider、同题、同预算闸）且失败/副作用有记录。
- [x] 结果回填本 ADR「验证结果」节；087 R06 标 ✅。

## 验证结果

**2026-10-06 正式出分**：三臂 × 3 轮 = 9 份落盘 JSON
（`data/evals/frozen-{-,nomem-,bash-}20261006T*.json`），同 provider
（deepseek 被测 / siliconflow judge）、同冻结题、`--budget 20` 未触顶，
被测总开销 ¥5.56。单轮汇总均值：

| 臂 | 完成率 | 质量分（参考） | 成本/轮 | 耗时/轮 | 介入/轮 |
|----|--------|--------------|---------|---------|----------|
| full（完整装配） | **19.3/23（84.1%）** | 4.32 | ¥0.61 | 261s | 10.0 |
| nomem（无记忆臂） | 14.7/23（63.8%） | 3.75 | ¥0.50 | 230s | 6.0 |
| bash（bash 基线） | 14.0/23（60.9%） | 4.10 | ¥0.74 | 441s | 0 |

- **臂有效性判据成立**：r7–r12 六条 seed 场景，full 14/18 通过 vs
  nomem 2/18。分题看：r7 3:0、r8 3:0、r9 3:0、r10 2:0——记忆注入链
  在四类记忆（旧 r7 模板 + 用户事实 + 进行中事项 + 产物基线）上全部
  显著起效。r11 仅 3:2：任务文本「用 PHP 写还是 Python 写」本身就能
  推出「PHP 做工具层」的常识结论，该题区分度天然弱（开发轮就该降级
  预期的题）。r12 全臂 0/9：见下。
- **执行收益判据成立**：full vs bash 完成率 84.1% vs 60.9%（+23.2pp），
  且成本更低（¥0.61 vs ¥0.74/轮）、耗时近半（261s vs 441s）——机制
  层（计划/确认缝/记忆）不是只加了安全，也带来了执行收益。bash 臂
  在机制题上系统性掉分：i4 0/3（无确认缝拦外发）、m1 0/3（无计划
  失败软拦）、i6 1/3、i5 2/3——这些掉分点与机制设计一一对应，正是
  「执行成功率收益」的正面证据。
- **介入次数注**：full 10 次/轮为确认缝的预期产物（policy=approve
  自动放行，非真人值守成本）；nomem 6 次/轮略低（记忆题早早答错，
  触发的高级操作更少）；bash 0 次为臂定义（无确认缝）。
- **失败与副作用如实记录**：污染命中（_contaminated）九轮全 0；fails
  条目 full 3–4/轮、nomem 7–10/轮、bash 8–10/轮，逐条在 JSON 里。
  两个全臂稳定失败模式值得点名（046：记录不改题）：
  1. **r1-research-report 0/9**：外部行情数据源不稳，港股缺口补全
     多轮失败（judge：报告未完成/笔记未保存）——真实调研任务的
     数据源依赖被冻结集如实暴露，非注入链问题。
  2. **r12-inv-naming 0/9**：agent 反复只产出空文件/伪代码，建不出
     可运行的 pytest 骨架（开发轮曾以 4/5 过一次，正式轮三臂全翻）。
     任务本身难度偏高的真实失败模式，留给出分后的机制 ADR 判断
     （例如确认缝要不要对「产物可运行性」加校验），本 ADR 不动。
- **逐题波动**：full 臂三轮 19/19/20，波动集中在 r2（2/3，子任务
  工具调用偶发错误）、r3（2/3，偶发编造图谱返回）、r4/r6 各一次偶发，
  无单轮特异失败——符合「≥3 轮同形态」的证据要求，未触发任何机制
  改动。
