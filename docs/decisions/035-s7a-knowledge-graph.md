# 决策记录 · S7a 知识图谱数据层（2026-09-23）

> S7 第一站：notes 的结构化投影——抽取管线+增量同步+查询工具。返回 [architecture.md](../architecture.md)

- **设计原则第 7 条的首个实证**：草案曾以「14 篇笔记才 289 行」论证砍范围，被用户纠正（能力建设优先——产品不是 demo，数据会追上来）后按一等公民规格建：别名对齐、关系白名单注册表、增量指纹同步、删除安全阀一次做全。

- **五拍板（开工草案定）**：
  - **P1 LLM 封闭抽取+三道防线**：关系白名单（graph.RELATIONS 单一真值源，提示词与校验共用）+现有实体清单挂靠（M6.4 记忆固化「已知清单传入」同款手法——「RAG」/「检索增强生成」归一不做平行节点）+禁推断铁律（只抽原文明确表达的关系）。
  - **P2 出处程序侧强制**：merge_note 签名带笔记名——模型没机会伪造出处，无出处的边不存在于合法路径上。出处防线不在提示词在签名（不信任模型自觉的老规矩）。
  - **P3 graph.json 进 git**：notes 的结构化投影是知识资产（文本可读可审查可 diff），与 vector_db 二进制缓存相反的判断；只在真有变更时落盘（防启动弄脏 git 工作区）。
  - **P4 查询三原语**：neighbors（关系过滤）/path（BFS ≤3 跳无向——「A 和 B 什么关系」不预设方向）/overview（统计+孤岛+枢纽——向量检索给不出全集，这是知识地图对个人知识管理的独特价值）。
  - **P5 界面可操作（用户拍板补做）**：图谱更新不能只是启动时隐式行为——sync_graph 工具上菜单（说「把它加进图谱」即触发）；force=true 全量重抽（换更强模型场景）；write_note 回灌闭环提示；子 agent 禁 sync_graph（_FORBIDDEN——执行者不动共享知识资产）。

- **实现结构**：graph.py（值对象 GraphNode/GraphEdge + GraphStore：三道校验闸门/merge_note 原子替换（删边留节点，孤岛 overview 报告人决）/邻接索引推导不落盘）+ extract.py（抽取+sync_graph 指纹差集管线，sync_notes 同构：没改不重抽/假模型不抽不记指纹/删除安全阀复用同款阈值）+ tools/graph.py（query_graph 三原语+sync_graph，错误串指路）。

- **实机验收（真模型 deepseek-flash+Jev+浏览器）**：启动全量抽取 14/14 零失败（33 概念/33 边）→ 查询路由（Jev `single_tool → query_graph`，模型自然组合三原语）→ 孤岛如实暴露（Embedding 零边）→ 界面写新笔记（write_note 提示生效、模型主动提议 sync）→ 增量抽取精准（1 篇新增/14 篇零成本）→ **孤岛连通**（Embedding 0→2 边，2 跳链路打通）。**产品闭环被完整演示：图谱缺口暴露笔记缺口 → 补笔记 → 增量抽取 → 缺口自愈——知识地图告诉你哪里没学透。**

- **已知边界（挂活清单，不阻塞）**：①`.md` 文件名被抽成实体（提示词可加「文件名不是实体」规则）②抽取建模口径随机（直连边 vs 桥接概念，语义等价——LLM 抽取固有特性）③单句定义型笔记天然孤岛（结构性：闭环=补笔记→重抽，验收已演示）。

  > **边界①状态更新（2026-09-25，[042](042-notes-panel.md)）**：当初写的触发信号是「S7b 可视化会让人眼更容易发现脏数据」——可视化落地后确实在图上看见了 `Agent.md`、`能力与政策一致性检查.md` 这类文件名实体，但**发现之后没有下一步**（不知道哪篇笔记贡献的、没法核对原文）。042 第 0 档补上这一步：图谱节点侧栏渲染 `GraphEdge.source_note`（「出自：X.md」）+ 深链 `/notes?n=X.md` 直达原文编辑。边界①本身（文件名仍被抽成实体）未消除，提示词侧规则仍挂活清单；变的是它从「不可诊断」变成「一眼可溯源、可就地修正」。

  > **消融实验结果（2026-09-25，evals/graph_ablation.py）**：roadmap 刺 #3 的预写规则——「场景按 L1/L2/L3 分级，预期图谱 L1 输、L2+ 赢；若 L2 也不赢，图谱降级为按需工具」。数据（词袋 / BGE-M3 两 embedder 同趋势）：**L1 打平**（BGE 4/4 vs 4/4，块数成本 1.75→2.2——论文⑥「L1 图谱带噪声」的预言成本侧成立；词袋下还意外 +1：实体名锚定是精确导航，词袋闸门误杀时图谱兜底）；**L2 图谱赢（词袋 0/4→2/4，BGE 2/4→3/4）→ 预写规则判定「有检索增量，值得继续投入」**；L3 各 +1。定性组：14 个孤岛 overview 直接列出 vs 向量检索硬凑无关碎片；path(政策, Embedding)=None 如实报告 vs 硬凑 Embedding.md 定义句答非所问——「给得出全集、防得住硬凑」是指纹命中率之外的独占价值。miss 归因：①Embedding.md 这类单句定义型笔记无出边（边界③的实锤），实体 BFS 2 跳拿不到向量数据库.md 贡献的边（要 3 跳）——**图覆盖盲区直接漏增量**，增量上限被抽取质量卡住；②每篇 top1 选块策略粗糙（政策簇主题词密集，指纹块未必得分最高）。下一步：检索分诊（事实走向量/多跳走图）具备立项数据——与 028 场景路由同一机制；「图谱降级为按需工具」的选项被数据否掉。

  > **反方读数（同日，用户挑战补录）**：实验是 2×2 因子设计（embedder × 是否加图），行内对照变量是图、跨行是稳健性重复——但**embedder 才是一阶效应，图谱是二阶增量**：L2 上词袋 baseline 0/4 → 换 BGE 不加图直接 2/4（+2），BGE 再加图谱才 3/4（+1），即「弱 embedder+图谱」打平「强 embedder 不加图」。单看命中率、资源只够二选一时，换 embedder 性价比高于维护图谱。图谱不可替代项仅剩：BGE 之上的净增量（L2/L3 各 +1 且不重合）、L3 多跳（BGE 单独 0/2）、定性组（全集/不连通——任何 embedder 结构性给不出的范式差异）。另需坦白：L2 仅 4 题且按图谱优势区间出题（刺 #4 自我出题嫌疑原位适用）——本结论强度 = 方向性决策依据（降级与否的二选一够用），不配当精确 ROI。

  > **语料侧诊断补录（同日，用户第三条挑战「图谱孤岛其实依赖用户语料，折腾这些测试数据没啥意义」）**：挑战成立。孤岛 14 个的归因诊断 = **5 单句定义型**（PHP/Python/RAG/上下文窗口/余弦相似度——原文只有定义句，禁推断防线在起作用，孤岛是正确结果）+ **9 表格维度噪声**（同一篇笔记的四层拆解表被逐格抽成实体：demo类项目/企业级课程/前沿论文/复杂任务/模型/论文/课程/项目等）+ **零个抽取漏**——短板 100% 在语料侧，抽取器无可改，补盲的正确动作在内容侧（042 面板即入口）。连带效力回烧上一条消融：10 题同为自建测试数据，「图谱有检索增量」的强度仅够当方向性依据（降级/不降级的二选一），不构成 ROI 证据。**处置**：043 实现不回滚（无条件导航的 L1 成本由图自然空集承担，真实语料下即使增量为 0，代价仅偶尔多 2 个块）；此后检索/图谱类机制不再自建题目验证，改走「042 面板喂真实语料 + 采集实机 miss」——043 已挂的 A 径触发信号「关系类答非所问 ≥2 次」即此口径。
