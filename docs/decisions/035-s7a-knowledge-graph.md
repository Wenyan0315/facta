# 决策记录 · S7a 知识图谱数据层（2026-09-23）

> S7 第一站：notes 的结构化投影——抽取管线+增量同步+查询工具。返回 [architecture.md](../architecture.md)

- **设计原则第 7 条的首个实证**：草案曾以「14 篇笔记才 289 行」论证砍范围，被用户纠正（能力建设优先——产品不是 demo，数据会追上来）后按一等公民规格建：别名对齐、关系白名单注册表、增量指纹同步、删除安全阀一次做全。

- **五拍板（开工草案定）**：
  - **P1 LLM 封闭抽取+三道防线**：关系白名单（graph.RELATIONS 单一真值源，提示词与校验共用）+现有实体清单挂靠（M6.4 记忆固化「已知清单传入」同款手法——「RAG」/「检索增强生成」归一不做平行节点）+禁推断铁律（只抽原文明确表达的关系）。
  - **P2 出处程序侧强制**：merge_note 签名带笔记名——模型没机会伪造出处，无出处的边不存在于合法路径上。出处防线不在提示词在签名（不信任模型自觉的老规矩）。
  - **P3 graph.json 进 git**：notes 的结构化投影是知识资产（文本可读可审查可 diff），与 vector_db 二进制缓存相反的判断；只在真有变更时落盘（防启动弄脏 git 工作区）。
  - **P4 查询三原语**：neighbors（关系过滤）/path（BFS ≤3 跳无向——「A 和 B 什么关系」不预设方向）/overview（统计+孤岛+枢纽——向量检索给不出全集，这是知识地图对个人知识管理的独特价值）。
  - **P5 界面可操作（用户拍板补做）**：图谱更新不能只是启动时隐式行为——sync_graph 工具上菜单（说「把它加进图谱」即触发）；force=true 全量重抽（换更强模型场景）；write_note 回灌闭环提示；子 agent 禁 sync_graph（_FORBIDDEN——执行者不动共享知识资产）。

- **实现结构**：graph.py（值对象 GraphNode/GraphEdge + GraphStore：三道校验闸门/merge_note 原子替换（删边留节点，孤岛 overview 报告人决）/邻接索引推导不落盘）+ extract.py（抽取+sync_graph 指纹差集管线，sync_notes 同构：没改不重抽/假模型不抽不记指纹/删除安全阀复用同款阈值）+ tools/graph.py（query_graph 三原语+sync_graph，错误串指路）。

- **实机验收（真模型 deepseek-flash+Jev+浏览器）**：启动全量抽取 14/14 零失败（33 概念/33 边）→ 查询路由（Jev `single_tool → query_graph`，模型自然组合三原语）→ 孤岛如实暴露（Embedding 零边）→ 界面写新笔记（write_note 提示生效、模型主动提议 sync）→ 增量抽取精准（1 篇新增/14 篇零成本）→ **孤岛连通**（Embedding 0→2 边，2 跳链路打通）。**产品闭环被完整演示：图谱缺口暴露笔记缺口 → 补笔记 → 增量抽取 → 缺口自愈——知识地图告诉你哪里没学透。**

- **已知边界（挂活清单，不阻塞）**：①`.md` 文件名被抽成实体（提示词可加「文件名不是实体」规则）②抽取建模口径随机（直连边 vs 桥接概念，语义等价——LLM 抽取固有特性）③单句定义型笔记天然孤岛（结构性：闭环=补笔记→重抽，验收已演示）。
