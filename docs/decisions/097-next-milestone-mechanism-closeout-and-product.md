## 背景

087 收官时留了一句话：「下一阶段目标是证明 Facta 在日常几类任务中稳定
减少返工与人工介入」。R06 九轮出分（096）与 R09 分发验证（095）同时
点亮了架构活清单里挂了很久的一批触发信号——这个里程碑的素材不是脑补
的优先级，是证据到期的清单：

1. **n=9 稳定失败模式**：r1（外部数据源 + plan-scope 围栏 + 预算耗尽
   复合，九轮全红，`llm_calls=8` 恒等式形状反复出现）、r12（建不出
   可运行测试骨架，九轮全红且早早放弃）。046 的「≥3 轮同形态」门槛
   早已越过，机制裁定的时候到了。
2. **plan-scope 围栏第三次及以后同类失败已发生**：R06 九轮里带
   `plan-scope` 的失败共 7 次（历史 2 次）——architecture 活清单
   「计划白名单声明过窄」条丙案（越界改走 L2 确认）的重新考虑信号
   兑现。
3. **spawn_step 编排评审到期**：七次观测非确定性偏向手工桥，活清单
   原文「触发信号＝下一轮编排机制评审」——本里程碑就是那个场合。
4. **VS Code 壳两道前置全清**：A 径记忆层 MCP 化（044）落地 +
   095 干净安装验证完成。
5. **B-lite 撒饵硬前置兑现**：338 条要求「真实语料消融拿到数字」，
   096 交的正是这个数字（记忆对执行成功率 +20.3pp）。
6. **tombstone/时效差一轮证据**：319 条触发信号是「连续两轮垫底」，
   目前只有一轮（058）——需要第二次 LongMemEval 锚定跑才能裁决。

## 边界（显式记录）

- N01/N02 是**评审产出裁定**，不是「必然改机制」——裁定可以是「不改，
  维持登记」，但必须给出 n=9 证据下的明确理由。
- N04 不做 IDE 内重写 UI（两个前端真值源正中摊薄刺）；LSP 诊断仍留
  触发信号（壳立项本可借宿主诊断，届时再议）。
- N05 跑分预算上限 ¥10，超即中断保读数（沿用 096 预算闸纪律）。
- N06 只撒饵不交付产品；第二个真实用户出现才谈 B（338 原裁定）。
- 暂缓项不因本里程碑解冻：Repo map、LSP、Hooks、快照/undo、会话树、
  S6d 角色化等触发信号一个都没兑现，维持原判。
