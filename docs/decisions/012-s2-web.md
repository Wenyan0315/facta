# 决策记录 · S2 · 分层清账与 Web 壳

> 迁自 docs/architecture.md 决策记录（2026-09-15 v0.37 拆分，内容原样保留）；append-only——修正与补充以新记录追加，不改写旧记录。返回 [architecture.md](../architecture.md)

- **S2a 分层清账（2026-09-15，S2 开工附带项）**：诊断——agent_loop 住 core/ 却 import memory/tools/knowledge，最底层反认上层（P1 依赖方向病的复发）；且 run_chat 体内 input/print 直出，Web 壳无法复用。裁定四件：①**编排层正名**——loop.py 迁 `orchestrator/`，定位「编排各层的编排层」；core/ 回归地基（types/llm 接口/网关/账本/向量数学），只被上层认识、不认识任何上层。②**内核/外设分离**——run_chat 拆成 `run_turn(session, user_text, ...)` 纯内核（零 input/print，I/O 走 `on_text`/`on_event` 两条回调缝，副作用归调用方注入——streaming 里程碑 on_text 缝的推广）+ `cli.py` 薄壳（input/print/退出词表）；Web 壳直接复用同一内核，「界面是壳内核不变」落到代码结构。③**装配单一真值源**——`orchestrator/assemble.py::assemble(provider) → AppContext`（provider/双 LLM 链/kb/session/registry/mcp_clients 一本账），CLI 与 Web 两个入口共用，`__main__` 只剩 argv 解析与多会话循环。④store 新增 `restore_session`（move 语义：归档读回 active 后删除归档）——S2b 会话切回的地基。验收：136 用例全绿 + CLI mock 冒烟逐项一致。

- **S2b Web 壳（2026-09-15，S2 v1 对话视图落地）**：选型落定 **FastAPI + SSE**——SSE 与 streaming 里程碑的增量协议同构（服务端单向推送够用，不上 WebSocket 双向）；前端静态三件（HTML/CSS/JS）零构建链；fastapi/uvicorn 进 pyproject `web` 可选组（与 chromadb 同纪律：教学路径不背重依赖）。**①Run 三接口分离**：POST /api/runs 创建（202 立即返回，后台 daemon 线程跑 run_turn）→ GET /api/runs/{id}/events SSE 订阅 → POST /api/runs/{id}/cancel。**断开 ≠ 取消**：浏览器断开后台照跑，事件落 Run Store，重连后 EventSource 自动带 Last-Event-ID 按 seq 重放缺的事件（重放段与实时段用 seq 哨兵去重）。**②Run Store 内存状态机**：pending→running→{completed|failed|cancelled}，**单一终态不变量**（finish 重复调用不覆盖；终态事件 run.{status} 先进事件流再发结束哨兵——客户端靠终态事件渲染成败，不靠「流断了」猜）；事件 append-only + seq 位置键（排序/去重/重放一键三用），schema_version 版本护栏；**单锁 create_if_idle 原子**——session 是共享可变对象，并发两个 Run 互踩 messages，多并发留 S6。Run/Step/Attempt 三层执行模型 v1 只显式建模 Run，Step/Attempt 落注释（YAGNI）。**③协作式取消**：run_turn 新增第三条缝 `should_cancel`，检查点=每次模型调用前+每次工具执行前（命中则掐半截轮、user 消息留底片、不发事件——cancelled 是 Run 级终态归调用方）；已知边界：流式生成中途无法即时中断（同步生成器），CLI 照旧走 KeyboardInterrupt 通道。**④SSE 编码纯函数**：encode_sse/encode_heartbeat 独立单测（协议边界不可测，下游 bug 全出现在字节里）；`json.dumps(ensure_ascii=False)` 中文原样且自动转义换行/引号/反斜杠防撕破单行 data 帧；心跳用 SSE 注释行（不占业务 seq）。**⑤安全默认只绑 127.0.0.1**（业界调研吸收：本机单人使用）；请求体 pydantic 校验（系统边界与工具层同一纪律）。**⑥会话切回**：/api/sessions 三端点复用 S1 store 原语——切出当前（save→复盘→归档→原地清）→ restore_session 切入 → **内存原地换血（clear+extend 绝不 rebind：search_history 闭包抓的是列表对象，S1 列表身份陷阱的正面应用）**；有 Run 在跑时禁切（409）。**⑦前端**：EventSource 按 event type 路由渲染、requestAnimationFrame 节流合并刷新、工具调用渲染为卡片；/tasks 占位返回「预留未实现」（双视图信息架构预留兑现）。测试新增 14 条（状态机/编码器纯函数/取消两检查点/FastAPI 壳全生命周期与 404），全量 136→150 + 2 live 跳过；curl 端到端验证 SSE 完整生命周期（run.started→text.delta 中文不丢→run.completed）。已知边界（各带触发信号）：Run Store 内存版（多实例部署换 Redis/DB）；切会话时 consolidate 全量复盘（since=0 简化）；单订阅者队列（多客户端同时订同一 Run 需扇出）。

- **S2 验收修复轮（2026-09-15，第一轮真实浏览器使用 8 条反馈）**：**①人设保证升级为装配不变量**——Web 入口曾跑过无人设会话（人设种子只住在 cli.py，assemble 漏种）：语言漂移、信息政策失效、自我认知靠编三大症状同根；修法 `assemble::ensure_persona`：空则种/缺则补（历史遗留无 system 文件头部补插，摘要游标随位移 +1 对齐——position 型状态在插入后必须重对齐）。**②SYSTEM_PROMPT 增自我画像**——真实技术栈清单（deepseek 网关/内置工具 8 件/BGE-M3+Chroma/JSON 记忆/分层名单）+「没有的能力不得声称有」负面清单 + 语言规则（用户语言回复）。治「介绍自己/架构/技术实现」的成串编造：自我知识不在检索语料里，模型只能靠通用知识填（GPT-4/FAISS/TF-IDF/OpenAI Embeddings 全是幻觉）——真实痛点兑现 M6.1「改 SYSTEM_PROMPT 旧会话用旧人设」tradeoff 的修复触发。**③取消检查点③（流中）**——`_cancel_aware_stream` 把底层流包成「每块到手前查取消」，命中即 close() 底层生成器（触发清理收连接）+上抛内部信号掐半截轮；检查点族齐了：模型调用前①+流中每块③+工具执行前②；「流式中途无法即时中断」v1 边界由真实痛点（点取消干等模型生成完+UI 零反馈）兑现修复。**④Web 每轮落盘**——_run_worker finally 落盘且先于终态哨兵：Web 常驻进程没有 CLI 的退出保存钩子，此前只在归档类操作时写盘，服务被杀丢掉上次归档以来全部对话（强杀丢数据边界的 web 版）。**⑤任务视图最小版**——/tasks 从占位 JSON 变真页面（Run 列表+状态徽章+交付摘要，5s 轮询）；Run 加 title（用户消息截 60）/preview（最终回复截 300）展示字段（不参与状态机）；GET /api/runs 新的在前（dict 插入序=创建序）。**⑥历史回放**——GET /api/messages 滤 system/tool/空 content 点菜轮（只讲故事线）；前端启动/切回后加载渲染（此前压根没有历史加载——刷新即白屏）。**⑦前端体验**——marked 渲染 md（vendored 本地文件离线可用；流中纯文本、终态一次成稿；**用户输入与工具结果永不进 innerHTML**——不可信内容注入防线）；Enter 发送/Shift+Enter 换行/isComposing 护住 IME 组合/Esc 取消；取消按钮即时反馈（「取消中…」）+ run.cancelled 终态显示「已取消本轮」；顺带修 error 事件监听与 EventSource 原生错误同名冲突（无 data 时守卫返回）。**⑧测试污染第二次烧身（事故记录）**——每轮落盘上线当天，test_app 生命周期测试把「你好/你好！」写进真实 session.json，覆盖了用户三轮真实对话；M6.3「测试污染」教训首次真烧掉用户数据，且备份在污染后才拍（时序盲区）。修法三件：test_app autouse fixture 隔离 MEMORY_PATH 到 tmp_path；验收流程加 sha256 前后校验（本次跑完全量 156 用例，真实会话文件哈希不变）；被覆盖数据从会话记录逐字恢复（第 3 轮回复在转录中截断于 1200 字，恢复至截断处并附恢复说明标记——诚实残差：数据状态本身要诚实，不假装完整）。测试 150→156（人设三分支/每轮落盘/流式取消 close 验证/messages 过滤/runs 排序/tasks 页面）。

- **会话标题提炼（2026-09-15，第二轮反馈：列表标题「不稳定」+「用 LLM 提炼」）**：诊断——会话列表标题 = `derive_title` 机械截取首句 20 字，首句是「你好」「2」这种时标签毫无信息量（列表一排看不出各段在聊什么）；上一轮的「不稳定」感知根因在此。裁定：标题从「首句派生」升级为「LLM 提炼会话主题」，核心工程取舍——**①提炼时机=归档时**（/new 那一刻）而非每次打开列表：列表可能很长，逐段提炼又慢又烧钱；归档是低频一次性动作，付一次成本，列表读取永远零 LLM 调用。**②存哪=归档文件内**（Session.title 字段）：归档文件是不可变历史快照（append-only），「另存标题」不会漂移——这推翻了 S1「标题派生不另存」旧裁定的理由（旧裁定防的是「内容改了标题忘同步」，而归档内容永不改，前提消失）。**③首句派生降级为 fallback**：LLM 提炼失败（LLMUnavailableError/空输出）→ None → 调用方 fallback derive_title，归档不因标题失败中断。**④提炼函数 `memory/title.py::summarize_title`**：读滚动摘要+尾窗 user/assistant 原文（滤 system/tool），internal_llm 调用（不穿语义档、tools=None 防递归）；store.py 保持纯数据不 import LLM，故提炼逻辑独立成文件。**⑤标题只看故事线**：system=人设、tool=中间产物都不参与主题判断。测试 156→165（提炼成功/引号剥离+截断/LLM 挂降级/空会话不烧 LLM/列表优先 title/旧归档 fallback/归档写 title 集成）。

- **learned 幻觉污染清理（2026-09-15，顺带发现）**：`data/learned/other.md` 被固化了 4 条污染条目，其中 2 条是模型编造（「FAISS/TF-IDF 检索」「交互层/逻辑层/工具层/存储层四层架构」——真实是 BGE-M3+Chroma、orchestrator/core/knowledge/memory/tools/server），2 条是已知设计常识（不该跨会话沉淀）。根因：M6.4 审查层用同模型 internal_llm，在真实运行时没能拦住「自我认知幻觉」——这正是 M6.4 剪裁记录里「审查升级跨供应商裁判→幻觉率实测 >0」触发信号的兑现。清理：恢复 other.md 至干净单条。已知边界（记录不修，等 S 阶段排期）：consolidate 审查层仍是同模型，幻觉率 >0 已实测，跨供应商裁判（LLM-as-judge 那套）应在工具/安全里程碑后落地。
