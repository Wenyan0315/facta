# 决策记录 · 知识语料面板（notes 只读列表 + 编辑保存）+ 图谱出处渲染（2026-09-25）

> [025](025-memory-panel.md) 之后的第四个面板；[035](035-s7a-knowledge-graph.md) 已知边界①的兑现。返回 [architecture.md](../architecture.md)

## 立项：三个取证事实

1. **notes 现在是「只增不改」的**：`write_note` 有 `if path.exists(): return "已存在同名笔记…"`（tools/notes.py）——agent 没有修改笔记的能力。用户发现语料里写错一句，既不能在对话里让 agent 改，也不能在 Web 上改，只能开 IDE。这是真缺口，不是锦上添花。
2. **图谱有出处却不给看**：`GraphEdge.source_note` 由程序强制（「无出处的关系拒收」），已经在 `GET /api/graph` 的 payload 里，前端一个字节都没渲染（只用了 `relation` 配色）。后果很具体：035 已知边界①「`.md` 文件名被抽成实体（『Agent.md』）」的触发信号写的是「S7b 可视化会让人眼更容易发现脏数据」——可视化做了，**发现之后没有下一步**（不知道哪篇笔记贡献的、没法去核对原文）。
3. **能重抽却不能核对**：图谱面板已有 `POST /api/graph/rebuild`（Web 壳已承担知识资产维护动作），却看不到被维护的原文。这个不对称比「没有 notes 面板」更值得修。

## 裁定（五条）

1. **编辑已有 ✅ / 新建 ❌**。新建仍归对话里的 `write_note`——查重闸门（`kb.search(min_score=0.85)`）只在工具层，Web 新建等于绕过它，与 [041](041-memory-panel-user-scope.md) 裁定 3「不做手工新增条目」同一口径：**面板是查看与修正的入口，不是无中生有的入口**。删除也不做（连带图谱 `remove_note` + 向量库清理，且用户未要求）。
2. **围栏必须复用工具层同款，且这一条是安全红线不是风格偏好**。`PUT /api/notes/{name}` 的 `name` 来自 URL 路径——比 learned 的白名单枚举（4 个固定文件名）危险一个数量级：`../../.env`、`../../../.ssh/id_rsa` 都是任意文件写。必须走 notes.py 同款四道：`resolve()` 后 `is_relative_to(NOTES_DIR.resolve())` + `.md` 后缀 + 拒子目录（`"/" in name`）+ 只碰已存在文件（`is_file()`，否则 404——与裁定 1 的「不新建」是同一段代码）。
3. **写盘用 P0-3 的原子写手法**（tmp + `os.replace`）。半截文件不可能被 `sync_notes`/`sync_graph` 读到——它们按内容指纹判变化，读到半截会把半截当新事实抽进图谱。
4. **陈旧要显式，不自动花钱**。保存成功后不自动重抽图谱（`sync_graph` 走 LLM，与 S7b「花钱的事人点」口径一致）；返回体带明确的陈旧标记 + 前端提示「原文已改，向量库与图谱仍是旧投影」，并给出两个动作：向量库同步（`sync_notes`，只花 embeddings）与图谱重建（引导去图谱面板既有按钮，不新开端点）。**不承诺即时生效**——与 041 风险 3 同款诚实。
5. **乐观锁这次要做**（与 041 裁定「不加乐观锁」不矛盾，风险等级不同）。041 拒的是「双标签行号错位」——低频手滑、代价一行、给三端点改协议不值。这里是**整文件盲覆盖**，且用户日常就在 IDE 里编辑同一批 md（写作时 `docs/competitive-roadmap.md` 正在 IDE 中打开）——两个写入者都长期在线，不是低频。做法取最便宜的形态：GET 返回内容 hash，PUT 带回来比对，不一致 → 409 + 「磁盘上的版本已变，重新载入再改」。不引入版本号字段、不落盘元数据。

## 风险

| # | 风险 | 对策 |
|---|---|---|
| 1 | **任意文件写**（`name` 来自 URL） | 裁定 2 的四道围栏 + 测试直接钉 `../../.env`、`../src/agent/paths.py`、`sub/a.md`、`a.txt` 全部 4xx；404/400 语义分开（越界=400，不存在=404） |
| 2 | **向量库陈旧 → 检索答出已删内容**（幻觉形态，比不答更糟） | 裁定 4：保存后显式陈旧标记 + 一键 `sync_notes`；不在保存路径里偷偷同步（花时间且失败语义混在保存里） |
| 3 | **图谱陈旧 → 图上关系与原文不符** | 同上，引导既有 rebuild 按钮；不自动重抽（花钱） |
| 4 | **与 IDE 双写互相覆盖** | 裁定 5 的 hash 乐观锁（409）；写盘原子（裁定 3） |
| 5 | **大文件/二进制塞进列表** | 列表只 `glob("*.md")`（与 `list_notes` 同款），带 size；单篇读取设上限（超限返回明确错误串而不是拖死浏览器） |
| 6 | **面板成为第二个写入者后，「谁改的」不可追溯** | 接受：notes 进 git，`git log`/`git diff` 就是审计线（这一点比 learned 用户级栏好——041 风险 1 的 git 不兜底在这里不成立） |

## 剪裁

- 第 0 档（**本篇内做**）：图谱面板渲染 `source_note`——点节点在侧栏列「出自：X.md、Y.md」。零后端改动，数据已在 payload 里。
- 不做：Web 新建笔记、Web 删除笔记、子目录、markdown 所见即所得编辑器（用 `<textarea>` 等宽编辑原文 + 预览另说）、版本历史 UI（git 已有）、多人协作/锁租约。
- 不做**方案 B**（给 agent 加 `edit_note` 工具，让对话能改语料）。触发信号=面板落地后仍出现「让 agent 改笔记」的真实需求。理由：面板改比在对话里描述「改哪儿」更快，B 的价值可能被 A 吃掉；且 agent 自改语料没人眼过一遍，漂移风险高于收益。
