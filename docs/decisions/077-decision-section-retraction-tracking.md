# ADR 077：决定节三段式对账——压缩前先落「撤回/取代」状态

- 状态：**已落地**
- 日期：2026-10-05
- 立项出处：[competitive-roadmap P2-1](../internal/competitive-roadmap.md)（记忆补全三件套之四：压缩/摘要前先落「撤回/取代」状态，防滚动摘要洗平「改主意」）
- 关联：073（摘要决定节——本案是其骨架深化）、074（learned 四态词表——「已取代/已撤回」复用同一对词）、032（条目腐烂实证）、076（reflect 异步化）

## 背景

FR（Fortunate Recall）的反直觉发现②：**滚动摘要会把「撤回的计划」洗成
「曾有个计划」**——用户先决定做 X、后来说「X 不做了」，摘要把两轮都吞掉
后只写「讨论过 X 计划」，撤回事件被洗平。cortex 的消费面恰好都有此病：

- 底片 append-only 不丢，但投影（`build_payload`）与固化复盘
  （`_transcript`）都只看「摘要 + 尾窗」——被摘要吞掉的区域，
  方向性只活在摘要的转述里；
- 073 决定节只列「**仍有效的**决定」——改主意发生后旧决定从节里
  **静默消失**，「A 被明确否决过」没有任何结构化痕迹：模型后续重提
  A 相关话题时不知道它被否决过，固化萃取（074 戊 supersede）也
  失去了「B 取代 A」的判据。

## 决策

### 甲：「先落状态」= 状态进摘要时就结构化，此后滚动只增不减

「压缩前先落状态」在 FR 原文语境是「挑最便宜的先上」链的第 4 步
（状态字段 074 → 过期规则层 074丁 → 陈旧率 075 → 压缩前先抽改主意）。
贵的做法（压缩路径上加模型抽取、或正则匹配 learned 条目自动打 tag）
被否：前者给高频压缩路径加 LLM 调用、且与 076 刚做的异步化背道而驰，
后者误杀在用条目的代价大于漏掉取代。**便宜且结构正确的落点**：
改主意第一次发生时，状态就作为决定节的结构化段落落进摘要——

`_SUMMARY_PROMPT` 决定节从单列表升级为**三段式**：

```
【关键决定与约束】
有效：…（仍有效的决定/承诺/约束）
被取代：旧决定 → 新决定（被本次对话推翻的）
已撤回：…（明确收回且无替代的）
```

段头词复用 074 learned 状态词表（`learned.STATUS_PREFIXES` 中的
「被取代/已撤回」——单一词表跨两个载体；「已过期」排除在外：时效
失效是 074 规则层的活，与「改主意」不同范畴）。空段省略（没有取代
轨迹就不写「被取代」段头）——段头在场与否因此成为程序可判的信号。
**逐条对账纪律**（prompt 主体要求）：合并旧摘要时，旧决定节的每一条
必须在新决定节三段之一落位——仍有效 → 「有效」；被新对话推翻 →
「被取代」（写明旧 → 新）；明确收回 → 「已撤回」；禁止静默消失。
「曾有个计划」式的洗平（撤回被洗成存在过）是被点名的病，撤回必须留痕。

### 乙：程序校验扩展——轨迹只增不减（073 宽容同款）

`maybe_compress` 在 `_summarize` 后已有 `_DECISION_TAG` 在场检查
（073）；本案新增**轨迹丢失检测**：旧摘要决定节含「被取代/已撤回」
子串而新摘要决定节不再含 → `logger.warning` 照用不阻断。语义：
**状态一旦落过，滚动合并不得再把它洗掉**——这是「先落状态」后那道
防洗平闸的程序兑现。宽容方向与 073 一致：不为格式漂移付重试 token，
观测攒触发信号。

### 丙：learned 侧零新代码——链条由「摘要保真」补全

「改主意 → learned 四态」的既有链条是 074 戊的 `_supersede_duplicates`
（新条目 vs 在用旧条目的语义取代检测），它缺的前提是固化材料没被洗平。
决定节三段式后：固化复盘材料（`_transcript` = 摘要 + 尾窗）里的取代
轨迹以结构化形式在场 → 萃取出「用 B」新条目时，supersede 有「B 取代
A」的判据 → learned 旧条目被打 `[被取代]`。摘要保真是缺的那块拼图，
learned 状态机制本身不动。

## 边界（诚实登记）

- **「该落没落」防不了**：程序只能检测「落了又洗」（轨迹子串在场性
  对比），不能判定「本次合并本该出现取代轨迹却没出现」——那需要
  旧决定节逐条与新对话的语义对照，P1-5 六段式摘要的活（073 边界
  同款限定，本案不重复立项）。
- **检测是子串级**：模型把段头写成「取代」（丢「已」）就检测不到
  ——宽容方向一致（073 锚点同样只认 `_DECISION_TAG` 字面），对抗性
  格式漂移不拦。
- **第一次落状态仍靠模型守 prompt**：三段式与对账纪律是指令层承诺，
  程序兑现只覆盖「轨迹不倒退」单向。实机若频发「该落没落」，
  触发信号见下。
- **决定节变长**：三段式比单列表多段头 → payload token 略涨（每段
  数 token 量级，可忽略）；换来的「A 被否决过」视野是投影的直接增益。

## 验收

三门全绿；新增测试：旧带「已取代」轨迹新丢失 → warning 照用；
轨迹无中生有（旧无新有）不报；两者皆无不报；073 既有决定节测试
（带节零 warning、缺节 warning）不回归。对应 roadmap P2-1 ④ 验收
口径：滚动摘要不再把「撤回/取代」洗平为「曾有个计划」——状态以
三段式结构落进摘要、程序检测防倒退、learned 侧经保真材料自然落态。

## 触发信号

- 实机「轨迹丢失」warning 频发（模型不守对账纪律）→ 议摘要重试或
  决定节结构化出参（split 出参，代价变高）
- 需要「该落没落」的语义级对照 → P1-5 六段式摘要立项时吸收本案
  对账纪律（与 073 边界同一条汇合路径）
- learned 里「被取代」误判成批出现 → 议 supersede 材料附带三段式
  决定节全文而非仅新条目
